## Context

The full-page story reader ([mobile/app/story/[id]/read.tsx](../../mobile/app/story/[id]/read.tsx)) is meant to display in landscape. It calls `ScreenOrientation.lockAsync(LANDSCAPE)` on mount and, until it believes the device is landscape, returns an early full-screen overlay ("Rotate your device — Stories read best in landscape mode") whose only action is **Close**.

Detection was:

```js
const isPortrait =
  orientation === ScreenOrientation.Orientation.PORTRAIT_UP ||
  orientation === ScreenOrientation.Orientation.PORTRAIT_DOWN ||
  height > width;
```

where `orientation` came from `getOrientationAsync()` + an `addOrientationChangeListener`.

**The bug:** the overlay can get permanently stuck — rotating the device does not dismiss it. Two compounding causes:

1. **The `|| height > width` fallback fights the lock.** The reader is opened from portrait screens, so on mount `width/height` are portrait and the overlay shows immediately. It only clears once the OS *actually rotates the window* so the dimensions flip — which depends entirely on the landscape lock succeeding.

2. **`lockAsync(LANDSCAPE)` silently no-ops in common situations**, and the original `catch {}` swallowed the failure: iPad with `supportsTablet: true` and no `UIRequiresFullScreen` (iOS ignores orientation locks for multitasking-capable apps), the iOS device-level portrait rotation-lock being on, and simulators. When the lock is a no-op the window never flips, `useWindowDimensions` keeps returning portrait, **and** `addOrientationChangeListener` never fires a landscape event (the *interface* orientation never changed — only the physical device). So `height > width` stays `true` forever and rotating the phone cannot clear the gate.

Net: a design that asks the user to rotate, but in the failure path rotating physically cannot satisfy the gate. This was reported in the wild ("the message doesn't go away when changing device orientation").

## Goals

- The reader must never trap the user behind an undismissable overlay.
- Preserve the "best in landscape" guidance without blocking reading.
- Keep best-effort landscape locking for the common (phone) case.

## Non-goals

- Forcing guaranteed landscape on iPad. Considered `UIRequiresFullScreen: true` in `app.json`; rejected — it disables Split View / Slide Over for the **entire** app and requires a native rebuild, too high a cost for one screen. iPads rotate freely, so they can't get "stuck" regardless.
- Adding a manual orientation toggle / portrait-optimized layout. The `Curl` already adapts to any dimensions.

## Proposed approach

Remove the blocking gate; always render the reader. Replace the full-screen overlay with a small, non-blocking, auto-dismissing hint.

In [read.tsx](../../mobile/app/story/[id]/read.tsx):

- Delete the `orientation` state, the `getOrientationAsync()` call, and the `addOrientationChangeListener` subscription — none are reliable signals for "can the user read this," and the listener is the thing that fails to fire when the lock no-ops.
- Compute `isPortrait` purely from `useWindowDimensions`: `const isPortrait = height > width;`. This always reflects the *actually-rendered* orientation, so it can never desync from what's on screen.
- Keep the landscape lock as best-effort, but `console.warn` on failure instead of swallowing it silently.
- Remove the `if (isPortrait) return <portrait overlay>` early return. The `Curl` is fully dimension-driven and renders correctly in portrait.
- Add a small `hintVisible` state, defaulting `true`, cleared by a `setTimeout` (~3.5s). Render a non-blocking pill ("Best read in landscape", `pointerEvents="none"`, Fade in/out) only while `isPortrait && hintVisible`.
- Replace the now-unused `portrait*` styles with a single `landscapeHint` / `landscapeHintText` style.

## Critical files

- `mobile/app/story/[id]/read.tsx` — the entire fix lives here: detection, the lock effect, the removed early return, the new hint, and styles.

## Reuse

- `useWindowDimensions` (already imported) — single source of truth for orientation.
- `Animated` + `FadeIn`/`FadeOut` from `react-native-reanimated` (already imported, used by the existing controls) — reused for the hint.

## Risks & mitigations

- **Risk:** Reading in portrait looks worse than landscape (text baked into illustrations is sized for landscape).
  - Mitigation: acceptable degradation — the alternative was an undismissable trap. The hint nudges toward landscape; the lock still rotates phones in the common case.
- **Risk:** Dropping the orientation listener loses some signal.
  - Mitigation: `useWindowDimensions` re-renders on dimension change, which is the only signal that matters for layout. The enum added nothing the dimensions didn't already convey, and was the unreliable part.

## Rollout

- Ship in mobile JS bundle. No backend, no native module change, no `app.json` change → works in the existing dev client and over OTA; no new EAS build required for the fix itself.
- Monitoring: confirm on a physical device with iOS portrait rotation-lock ON that the reader still opens and is readable (the original repro).
- Rollback: revert the single-file change / PR.
