The TestFlight beta expired and a new build (18) is about to go to testers. The backend must be
on supported models **before** that build is smoke-tested, because the on-device preflight
generates a real story.

Evidence gathered before this plan was written:

- **Free `models.list` call against the production key (2026-11-09):** all six candidate IDs are
  served and every one lists `generateContent` in `supportedGenerationMethods` —
  `gemini-3-flash-preview`, `gemini-3.6-flash`, `gemini-3.8-flash`,
  `gemini-3.1-flash-image-preview`, `gemini-3.1-flash-image`, `gemini-nano-banana-2.1`.

  API rewrite and no SDK upgrade are required** for this change.
- **Google's docs** now show image generation only through the Interactions API and state that
  image-model thinking "is enabled by default and cannot be disabled", that the model
  "generates up to two interim images", and that Nano Banana 2.1 defaults to `medium` thinking

  only `includeThoughts`, so the thinking level cannot be set from this SDK. It **does** pass the
  `thought` flag through on response parts (`genai.d.ts` `Part.thought`).
- **Separate production outage found while probing (not a code problem):** every paid call
  returns `402 Payment Required — "Your prepayment credits are depleted"`. Generation is down on
  every model until the owner tops up credits in AI Studio. That also blocks this plan's live

## Goals

- Production pins **GA** model IDs: `gemini-nano-banana-2.1` for images, `gemini-3.8-flash` for
  story text and both moderation classifiers.
- Image extraction can never keep a draft: interim "thinking" images in a response are skipped
  and the final image is the one uploaded.
- A test fails if anyone re-pins a preview / experimental / `-latest` alias model ID.
- Docs (`CLAUDE.md`, `README.md`) name the models actually in use.

## Non-goals

- **No `@google/genai` upgrade and no Interactions API migration.** That is FC-042. A dependency
  jump from 0.7.0 to 3.0.0 changes safety enums, response shape and retry semantics; it must not
  ride along with an urgent model swap.
- **No thinking-level, `imageConfig`, aspect-ratio or resolution config.** SDK 0.7.0 cannot send
  them. The FC-028 prompt-level 16:9 instruction stays exactly as is.
- **No env-var override for model IDs.** Rollback already exists without one (see Rollout), and a
  service-level env var that survives deploys is the kind of hidden state this repo has been
  burned by (see the pinned flags in `cloudbuild.yaml`).
- **No runtime fallback chain** (try model A, then B). Tuned prompts and OCR thresholds assume
  one model; silently switching mid-story would make failures unattributable.
- No prompt changes, no threshold changes (`TEXT_RECALL_MIN`, `TEXT_PRECISION_MIN`,
  `PROD_TEXT_GEN_ATTEMPTS`, `PAGE_GEN_CONCURRENCY`, moderation timeouts), no retry-classifier
  changes, no stage-event shape changes, no mobile changes.
- No billing / credit-depletion alerting (FC-046).

## Proposed approach

### 1. New pure module `backend/src/services/imageResponse.ts`

```ts
export interface GeneratedImage { data: string; mimeType: string }

export function extractGeneratedImage(response: ImageResponseLike | null | undefined): GeneratedImage | null
```

`ImageResponseLike` is a local structural type (do **not** import SDK types — the module must stay
pure and SDK-free, like `textVerify.ts`):

```ts
type ImagePartLike = { inlineData?: { data?: string; mimeType?: string }; thought?: boolean };
type ImageResponseLike = { candidates?: Array<{ content?: { parts?: ImagePartLike[] } }> };
```

Behavior contract:

- Looks only at `candidates[0].content.parts`.
- A part counts as an image when `inlineData.data` is a non-empty string.
- Parts with `thought === true` are **ignored** (interim images and thought text).
- Returns the **last** remaining image part. Google documents the final rendered image as the
  last one; with a single-image response "last" and "first" are the same part.
- `mimeType` defaults to `'image/png'` when missing or empty (matches today's fallback).
- Returns `null` when there is no non-thought image (no candidates, no parts, text only, or
  thought images only). **Never falls back to a thought image** — a draft must not reach a child's
  book.

### 3. Tests

`backend/src/services/__tests__/imageResponse.test.ts` — pure unit tests, no mocks:

| Case | Expect | Regression it catches |
|---|---|---|
| `[thought image, thought text, final image]` | final image's data + mimeType | keeping a draft image |
| `[final image]` | that image | breaking the common single-part case |
| `[thought image]` only | `null` | falling back to a draft |
| `[text]` only / empty parts / no candidates / `null` / `undefined` | `null` | crash on blocked or empty responses |
| image part with empty-string `data` | skipped | treating an empty payload as an image |
| image part without `mimeType` | `'image/png'` | losing today's default |
| `[image A, image B]`, neither a thought | image B | "last wins" rule drifting |

`backend/src/services/__tests__/gemini-models.test.ts` — call-site tests. Mirror the
mock-before-import pattern in `gemini-aspect.test.ts` (same `vi.hoisted` env setup, same
`@google/genai` enum stubs, Vision mock that throws so OCR fails open), with two differences:
the Storage mock must **capture** every `file(name).save(buffer, opts)` call, and the
`generateContent` mock must branch on `config.responseModalities`:

- Image call (`responseModalities` includes `'IMAGE'`) → parts
  `[ {inlineData:{data: b64('DRAFT'), mimeType:'image/png'}, thought:true}, {text:'planning', thought:true}, {inlineData:{data: b64('FINAL'), mimeType:'image/jpeg'}} ]`.
- Text call → an object with a `text` property. Return a valid minimal story JSON when the
  prompt is the story prompt, otherwise `'{"verdict":"safe","category":"none","reason":"ok"}'`.
  (Simplest: return the story JSON for a string `contents` that the test passes via
  `generateStory`, and the verdict JSON for the two moderation wrappers — choose any robust
  discriminator and comment it.)

Assertions:

1. **Final image is what gets stored, at every image call site.** For each of
   `generateIllustration` (with `{ verifyText: false }`), `generateCharacterReference`,
   `generateCastReference`, `generateTitlePage`: the saved buffer decodes to `FINAL`, the saved
   filename ends in `.jpg` (mime type of the final part was honored, not the draft's), and where
   the function returns `imageBase64` it equals `b64('FINAL')`.
   *Catches:* a call site left on the old first-image loop.
2. **Model routing policy.** Drive all seven call sites (`generateStory`,
   `generateModerationText`, `generateVisionModerationText`, plus the four image functions) and
   assert on the captured `model` values: the four image calls share one ID; the three text calls
   share one ID; the two IDs differ; and **no** ID matches `/preview|exp|latest/i`.
   *Catches:* re-pinning a preview or alias model, or a call site hard-coding its own model.
   Do **not** assert the literal model strings — that would only lock in today's constant.

Existing tests must stay green unmodified. If one fails, that is a signal the behavior contract
above was broken — fix the code, not the test.

## Design decisions already made (do not re-litigate)

| Decision | Chosen | Rejected, and why |
|---|---|---|
| Image model | `gemini-nano-banana-2.1` | `gemini-3.1-flash-image`: the GA build of what we run today, so lowest behavioral risk, but Google deprecated it on 2026-10-06 — choosing it books another migration. It is the **pre-approved fallback** (see Live verification). `gemini-3-pro-image`: ~4× the listed price and the slow tier FC-002 already moved off. `gemini-3.1-flash-lite-image`: documented as "not optimized for multiple reference inputs", which is this pipeline's core mechanism. |
| Text model | `gemini-3.8-flash` | `gemini-3.6-flash`: Google's named replacement, same listed price, but already labeled "previous-generation"; 3.7 was auto-routed to 3.8 within two months, so the newest ID has the longest runway. It is the **pre-approved fallback**. `gemini-3.5-flash-lite`: cheaper, but the same model runs both fail-closed safety classifiers for a children's product — not the place to economize. Staying on `gemini-3-flash-preview`: works today, but leaves the outage class this FC exists to remove. |
| Thought parts | Skip them; take the last non-thought image; never fall back to a draft | Keeping "first image" and hoping the API omits thoughts by default: unverifiable until credits are restored, and wrong the day Google changes the default. |
| Where the helper lives | New pure module | Private function in `gemini.ts`: untestable without mocking three SDKs at import. |
| Test policy | Ban `preview` / `exp` / `latest` IDs by pattern | Asserting literal IDs: an implementation-detail test that fails on every legitimate upgrade. |
| SDK | Stay on 0.7.0 | Upgrade now: separate risk surface (FC-042). |

## Risks & mitigations

- **Text-in-image accuracy or character consistency differs on the new image model.** Prompts and
  OCR thresholds were tuned on Nano Banana 2.
  - Mitigation: live verification compares first-attempt OCR pass rate against
    `gemini-3.1-flash-image` on the real prompt builder before merge; pre-approved fallback;
    post-deploy guardrail.
- **Slower and costlier images.** `medium` default thinking is billed and cannot be lowered on
  this SDK. The pipeline is already latency-sensitive (FC-016).
  - Mitigation: live verification measures latency side by side; fallback rule below. FC-042
    becomes the path to `thinkingLevel: minimal`.
- **Moderation gates start blocking every story.** Both classifiers are fail-closed with a 30 s
  timeout and a strict-JSON verdict; a slower or chattier text model turns into 100 % blocks.
  - Mitigation: live verification runs the real `moderateStory` / vision-moderation code paths
    against the new model with benign and unsafe fixtures and measures latency against the
    timeout.
- **Safety blocks reported in a new shape** (e.g. `finishReason` instead of
  `promptFeedback.blockReason`, or an HTTP 400) so a block is surfaced as `generation_error`
  rather than `safety_blocked`.
  - Mitigation: record the observed shape in Execution notes. Out of scope to change unless
    benign content fails; fail-closed means the unsafe path still blocks either way.
- **Rate limits differ for the new IDs** and `429` is not retried by `isRetryableError`.
  - Mitigation: live verification fires image calls at production concurrency (4).
- **Stable IDs auto-route when Google deprecates them** (3.5→3.6, 3.7→3.8 already happened), so
  behavior can change under a fixed ID.
  - Mitigation: accepted; it is strictly better than a hard shutdown. FC-046 covers detection.

## Rollout

1. PR merges to `main` → Cloud Build trigger `deploy-storybook-api` (path filter `backend/**`,
   region `us-central1`) runs `npm ci`, `npm test`, builds and deploys. No manual deploy step.
2. Confirm: `gcloud builds list --region=us-central1 --limit=1`, new revision serving,
   `/health` 200.
3. Owner runs the mobile release preflight on TestFlight build 18 — step 3 (generate a story
   end-to-end) is the first real story on the new models.
4. **Rollback (instant, no deploy):**
   `gcloud run services update-traffic storybook-api --region us-central1 --to-revisions=storybook-api-00163-685=100`
   (the revision serving before this change; old model IDs are still listed for our key as of
   2026-11-09), then `git revert` the merge commit so the next deploy does not undo the rollback.
5. **Post-deploy guardrail — first 5 real stories.** From the stage-event and `text-verify`
   logs: revert the **image** model to `gemini-3.1-flash-image` if any story ships a placeholder
   page for a non-transient reason, or if more than 1 page in 10 is kept below the OCR threshold
   after regeneration. Revert the **text** model to `gemini-3.6-flash` if 2 or more benign
   stories are blocked by either moderation gate.
