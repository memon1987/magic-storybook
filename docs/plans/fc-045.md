## Context

The backend pins two Gemini **preview** model IDs in `backend/src/services/gemini.ts`:

| Constant | Today | Google's status (docs read 2026-11-09) |
|---|---|---|
| `IMAGE_MODEL` | `gemini-3.1-flash-image-preview` | Deprecated. Earliest shutdown **2026-06-25** (already past). Not on the models page. Named replacement: `gemini-nano-banana-2.1`. |
| `TEXT_MODEL` | `gemini-3-flash-preview` | Still listed, no shutdown date. Preview models get at least 2 weeks' notice. Named replacement: `gemini-3.6-flash`; newest Flash is `gemini-3.8-flash`. |

The TestFlight beta expired and a new build (18) is about to go to testers. The backend must be
on a supported image model **before** that build is smoke-tested, because the on-device
preflight generates a real story.

**Scope decision (owner, 2026-11-09, after review round 1): this FC changes the image model
only.** `TEXT_MODEL` also runs both fail-closed safety classifiers; changing it changes how
every story is judged, and that needs a labelled safety evaluation that does not exist yet. The
text / moderation model moves to **FC-047**. The first draft of this plan changed both.

Evidence gathered before this plan was written:

- **Free `models.list` call against the production key (2026-11-09):** all six candidate IDs are
  listed and every one lists `generateContent` in `supportedGenerationMethods`. This proves the
  *method* exists for the model. It does **not** prove the request config is accepted or that a
  listed ID is served as-is (Google reroutes some deprecated IDs). Only a successful live call
  does — see Live verification.
- **Google's docs** now show image generation only through the Interactions API and state that
  image-model thinking "is enabled by default and cannot be disabled", that the model
  "generates up to two interim images", and that Nano Banana 2.1 defaults to `medium` thinking
  (Nano Banana 2 defaulted to `minimal`). Output "matches the input image's size, or otherwise
  produces a 1:1 square" when no ratio is requested.
- **The installed SDK is `@google/genai` 0.7.0** (latest is 3.0.0). It silently drops
  `thinkingLevel` and `imageConfig` from requests, so neither the thinking level nor a
  config-level aspect ratio can be sent. It keeps `thought` on response parts, and surfaces
  `modelVersion`, `usageMetadata` and `finishReason`.
- **Separate production outage found while probing (not a code problem):** every paid call
  returns `402 Payment Required — "Your prepayment credits are depleted"`. Generation is down on
  every model until the owner tops up credits. That also blocks Live verification. Follow-up:
  FC-046.

Sources: `aistudio.google.com/docs/` pages `deprecations`, `models`, `pricing`,
`image-generation`, `changelog`, `models/gemini-nano-banana-2.1`, `migrate-to-interactions`,

## Goals

- The image model is on a GA ID: `gemini-nano-banana-2.1` (pre-approved fallback
  `gemini-3.1-flash-image`, decided by Live verification).
- Image extraction can never keep a draft: interim "thinking" images in a response are skipped
  and the final image is the one uploaded.
- Tests fail if anyone pins a *new* preview / experimental / `-latest` model ID, or drops or
  weakens the safety settings on any Gemini call.
- Every Gemini call logs which model actually served it, why it finished, and what it cost in
  tokens — so a silent reroute, a safety block or a cost jump is visible in logs.
- Docs (`CLAUDE.md`, `README.md`, rollback runbook) are correct.

## Non-goals

- **No text / moderation model change.** `TEXT_MODEL` stays `gemini-3-flash-preview`. → FC-047.
- **No `@google/genai` upgrade, no Interactions API migration, no direct-REST image calls.**
  → FC-042. A jump from 0.7.0 to 3.0.0 changes safety enums, response shape and retry semantics.
- **No thinking-level, `imageConfig`, aspect-ratio or resolution config.** SDK 0.7.0 drops them.
  The FC-028 prompt-level 16:9 instruction stays exactly as is.
- **No env-var override for model IDs** and **no runtime fallback chain.** Cost of this choice,
  stated plainly: the instant rollback lands on the old preview IDs; moving to the GA fallback
  needs a PR, CI and a deploy (about 10 minutes).
- No prompt changes, no threshold changes (`TEXT_RECALL_MIN`, `TEXT_PRECISION_MIN`,
  `PROD_TEXT_GEN_ATTEMPTS`, `PAGE_GEN_CONCURRENCY`, moderation timeouts), no retry-classifier
  changes, no `stage_done` event changes, no mobile changes.
- No change to how safety blocks are classified or surfaced, and no new moderation of reference
  images. → FC-048.
- No billing / credit-depletion alerting. → FC-046.

## Proposed approach

### 1. New pure module `backend/src/services/imageResponse.ts`

```ts
export interface GeneratedImage { data: string; mimeType: string }

export function extractGeneratedImage(response: ImageResponseLike | null | undefined): GeneratedImage | null
```

`ImageResponseLike` is a local structural type (no SDK import — the module stays pure, like
`textVerify.ts`):

```ts
type ImagePartLike = { inlineData?: { data?: string; mimeType?: string }; thought?: boolean };
type ImageResponseLike = { candidates?: Array<{ content?: { parts?: ImagePartLike[] } }> };
```

Behavior contract:

- Looks only at `candidates[0].content.parts`.
- A part counts as an image when `inlineData.data` is a non-empty string.
- Parts with `thought === true` are **ignored**, wherever they appear in the list.
- Returns the **last** remaining image part.
- `mimeType` defaults to `'image/png'` when missing or empty.
- Returns `null` when there is no non-thought image. **Never falls back to a thought image.**

### 3. `backend/src/services/instrumentation.ts` — additive, log-only call telemetry

The per-call `call` event (emitted by `instrumentedGenerateContent` for all seven call sites)
gains optional fields on the **success** path. Nothing is removed or renamed.

- `CallEvent` gains: `modelVersion?: string`, `finishReason?: string`, `blockReason?: string`,
  `promptTokens?: number`, `outputTokens?: number`, `thoughtTokens?: number`,
  `totalTokens?: number`.
- New exported pure function `responseTelemetry(result: unknown)` returning those fields. It
  reads, defensively, from a response-like object: `modelVersion`,
  `candidates[0].finishReason`, `promptFeedback.blockReason`, and from `usageMetadata`:
  `promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount`, `totalTokenCount`. A field is
  included only when present with the right type (string / finite number). It **never throws**:
  any unexpected shape, including a throwing getter, yields `{}`.
- `instrumentedGenerateContent` success path spreads `responseTelemetry(result)` into the event.
- Must not change: the returned value, the failure path, rethrow behavior, existing fields.
- Must not log: `finishMessage`, any part text, any prompt text (may contain a child's name or
  story content). The seven fields above are enums, numbers and a model string only.
- The builder checks `node_modules/@google/genai/dist/genai.d.ts` and reports which of the four
  usage fields SDK 0.7.0 actually surfaces (`thoughtsTokenCount` may be absent).

### 4. Tests

`backend/src/services/__tests__/imageResponse.test.ts` — pure unit tests:

| Case | Expect | Regression it catches |
|---|---|---|
| `[thought image, thought text, final image]` | final image's data + mimeType | keeping a draft image |
| `[final image, thought image]` | final image | a thought part placed after the final image |
| `[final image]` | that image | breaking the common single-part case |
| `[thought image]` only | `null` | falling back to a draft |
| `[text]` only / empty parts / no candidates / `null` / `undefined` | `null` | crash on blocked or empty responses |
| image part with empty-string `data` | skipped | treating an empty payload as an image |
| image part without `mimeType` | `'image/png'` | losing today's default |
| `[image A, image B]`, neither a thought | image B | "last wins" rule drifting |

`backend/src/services/__tests__/gemini-models.test.ts` — call-site tests (mock-before-import
pattern from `gemini-aspect.test.ts`; Storage mock captures saves; `generateContent` mock
branches on IMAGE modality):

1. **Final image is what gets stored, at every image call site** (four tests, one per site).
2. **Safety settings are sent on every call.** For all seven call sites, `config.safetySettings`
   contains exactly the four categories (`HARASSMENT`, `HATE_SPEECH`, `SEXUALLY_EXPLICIT`,
   `DANGEROUS_CONTENT`), each at `BLOCK_LOW_AND_ABOVE`.
   *Catches:* a call site dropping the settings, or a threshold being weakened.
3. **Model routing policy.** Across all seven call sites:
   - the four image calls share one model ID;
   - no text call uses the image model ID;
   - every model ID either does **not** match
     `/(^|-)(preview|exp|experimental|latest)(-|$)/i`, or is in an explicit allow-list
     `ALLOWED_PREVIEW_IDS = ['gemini-3-flash-preview']` whose comment cites FC-045 / FC-047.
   - Do **not** assert that the three text calls share one ID — FC-047 may split the moderation
     model from the story model.
   - Do **not** assert literal model strings other than the allow-list entry.
   *Catches:* pinning a new preview or alias ID anywhere; a call site hard-coding the image model
   for text or vice versa.

`backend/src/services/__tests__/instrumentation.test.ts` — add:

- success event carries the seven fields from a realistic response object;
- fields absent from the response are absent from the event (not `undefined`-valued keys that
  serialize oddly, not `null`);
- a result that is a string, `null`, or an object with a throwing getter does not throw and the
  wrapper still returns the original result;
- the failure-path event is unchanged.

Existing tests stay green unmodified.

## Risks & mitigations

- **Text-in-image accuracy or character consistency differs on the new image model.**
  - Mitigation: Live verification runs the real pipeline, including the real OCR
    verify-and-regenerate loop, with absolute gates; pre-approved fallback; post-deploy guardrail.
- **Slower and costlier images.** `medium` thinking is billed and cannot be lowered on this SDK.
  Listed prices: image output is cheaper ($30 vs $60 per 1M tokens) but image *input* is 3×
  ($1.50 vs $0.50 per 1M) — and this pipeline sends up to 13 reference images per page — and
  thinking tokens are billed. The app tells users generation "usually takes 2–5 minutes" and
  build 18 has no over-the-air update.
  - Mitigation: Live verification has an absolute end-to-end time gate and prints token usage
    for a cost estimate; fallback rule; FC-042 is the path to `minimal` thinking.
- **Pages come out square.** With no ratio in the request, Google documents a 1:1 default; the
  16:9 pin is prompt-level only.
  - Mitigation: Live verification asserts every page and the cover is landscape.
- **The model returns a file type the pipeline mislabels.** `gcsDownload.ts` infers mime from the
  extension and assumes PNG or JPEG; vision moderation reads through that path and fails closed,
  so a third format could block every story.
  - Mitigation: Live verification asserts every generated image is PNG or JPEG and runs vision
    moderation through the real `downloadRef` path. If the assertion fails: stop; a code fix is
    required before merge.
- **A new image distribution trips the (unchanged) vision gate on benign pages.**
  - Mitigation: Live verification runs the real vision gate on every generated page and cover of
    two stories in two art styles (18 images).
  - **Accepted limit:** 18 images cannot rule out a moderate false-block rate — a 10 % per-image
    rate (which would block most stories) would still pass this check about 15 % of the time.
    Accepted because the failure mode is fail-closed (a blocked story, not unsafe content), the
    post-deploy guardrail watches for it, and rollback is instant. Measuring it properly is
    FC-047.
- **Image safety blocks are easy to miss.** A block reported only as `finishReason` produces a
  placeholder page and the story still completes (existing behavior, FC-048).
  - Mitigation: the new call telemetry logs `finishReason` / `blockReason`, so the post-deploy
    guardrail can be evaluated from logs.
- **Rate limits differ for the new ID** and `429` is not retried.
  - Mitigation: Live verification runs at production concurrency and gates on zero 429s.
- **Stable IDs are rerouted when Google deprecates them**, so behavior can change under a fixed
  ID (`gemini-3.7-flash` was rerouted eight weeks after GA).
  - Mitigation: `modelVersion` is now logged on every call, so a reroute is visible. Nothing
    *alerts* on it yet — that is added to FC-046's scope. A `models.list` check alone cannot
    detect a reroute.
- **`TEXT_MODEL` remains a preview ID** and can be retired with about two weeks' notice. Both
  classifiers fail closed, so the failure mode is an outage, not unsafe content.
  - Mitigation: accepted for this FC; FC-047 is the fix, FC-046 the detection.
- **The first story through the deployed service happens at the on-device preflight.** Live
  verification runs the real pipeline locally, but not Cloud Run, Firestore or GCS.
  - Mitigation: accepted; the preflight is a mandatory gate before testers get the build, and
    rollback is instant.

## Rollout

1. PR merges to `main` → Cloud Build trigger `deploy-storybook-api` (path filter `backend/**`,
   region `us-central1`) runs `npm ci`, `npm test`, builds and deploys.
2. Confirm: `gcloud builds list --region=us-central1 --limit=1`; new revision serving 100 %
   (`gcloud run services describe storybook-api --region us-central1 --format='value(status.latestReadyRevisionName,status.traffic)'`);
   `/health` 200.
3. Owner runs the mobile release preflight on TestFlight build 18 — "generate a story
   end-to-end" is the first real story on the deployed change.
4. **Rollback.** Resolve the previous revision at merge time (it was `storybook-api-00163-685`
   on 2026-11-09; any backend merge in between changes it):
   ```bash
   # a. instant: send traffic to the previous revision
   gcloud run services update-traffic storybook-api --region us-central1 --to-revisions=<PREVIOUS_REVISION>=100
   # b. revert the merge on main; wait for the Cloud Build deploy to finish
   # c. REQUIRED: un-pin, or this and every later deploy builds green and serves 0 %
   gcloud run services update-traffic storybook-api --region us-central1 --to-latest
   # d. verify
   gcloud run services describe storybook-api --region us-central1 --format='value(status.latestReadyRevisionName,status.traffic)'
   ```
   Step (a) pins the service to a named revision; Cloud Run then keeps that split for every
   later deployment until `--to-latest` is run. `cloudbuild.yaml` passes no traffic flags.
   **What the rollback lands on:** the previous revision runs the old image preview ID, which is
   past its listed shutdown date. Live verification records whether that ID still generates
   (probe `image` phase). If it does not, rolling back restores nothing — the real rollback is
   then the GA fallback `gemini-3.1-flash-image` via a one-line PR.
5. **Post-deploy guardrail — first 5 real stories, evaluated from logs.**
   - Switch the image model to `gemini-3.1-flash-image` if any of:
     - a `stage_done` event with `stage: "page"`, `outcome: "failure"` in a story that had no
       failed `call` event with `errorClass` of `unavailable` / `internal` / `high_demand` /
       `5xx` / a network class (`call` events carry no page number, so this is decided per
       story: a placeholder in a story with no transient call failures);
     - more than 1 in 10 `stage: "page"` success events with `detail.ocrPassed: false`;
     - any `call` event with `kind` of `page` / `title_page` / `char_ref` / `cast_ref` and a
       `finishReason` other than `STOP`, on a story the owner generated from benign inputs;
     - `stage: "all_illustrations"` `latencyMs` above 300 000 on a medium (6-page) story, twice.
   - A story the owner generated from benign inputs being blocked by the vision gate
     (`stage: "vision_moderation"`, `outcome: "failure"`) is a stop-and-investigate, not an
     automatic revert: the gate did not change, the images did.
