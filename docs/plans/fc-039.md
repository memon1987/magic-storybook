## Context

Deleting a story today is undiscoverable: long-pressing a card in the library ([`mobile/app/(tabs)/index.tsx`](../../mobile/app/(tabs)/index.tsx), `handleStoryLongPress`, lines 81–94) pops a confirm `Alert` and deletes via `deleteMutation` → `deleteStory` ([`mobile/services/api.ts`](../../mobile/services/api.ts) line 206, `DELETE /api/stories/:id`). Nothing hints that long-press does anything, and there is no visible delete target. Replace it with the familiar **iOS home-screen edit mode**: long-press → all cards jiggle with a delete badge; tap the badge → confirm → delete; Done/empty-space/navigate-away exits.

Decision already made (FC entry open question resolved): **confirm-dialog, NOT undo-snackbar.** Stories cost ~$0.50–$1 and minutes to regenerate; a confirm `Alert` is the familiar safe pattern and far less code than a snackbar + delayed-mutation queue.

## Goals

- Discoverable, familiar delete: long-press any card → edit mode with staggered jiggle + per-card "−" badge; badge tap → confirm Alert → optimistic delete.
- Clean exits: Done button (header right), tap on empty list space, and screen blur/unmount all leave edit mode.
- Accessibility: no jiggle under reduced motion (badges still shown); screen readers can delete via `accessibilityActions` on every card, without needing edit mode at all.
- Light haptics on entering edit mode and on delete confirm.

## Non-goals

- No reordering/drag of cards (iOS edit mode implies it; we only do delete).
- No undo-snackbar, no soft-delete/trash on the backend, no batch multi-select delete.
- No changes to `deleteStory` API, backend routes, or the FC-026 responsive grid math (`useResponsive`/`gridColumns`).
- No global state — edit mode is local `useState` in the library screen only.

## Proposed approach

### 1. Edit-mode state — `mobile/app/(tabs)/index.tsx`

- `const [isEditing, setIsEditing] = useState(false);` — local state, no context/store.
- **Enter:** `handleStoryLongPress` is rewritten: it no longer shows the delete `Alert`; it calls `Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light)` (see §5) and `setIsEditing(true)`. Long-press while already editing is a no-op.
- **Exit paths (all → `setIsEditing(false)`):**
  - **Done button:** while `isEditing`, the header-right slot renders a "Done" pill **replacing** the count badge (the header today is `headerLeft` title/subtitle + a 36pt-high `countBadge` pill showing `stories.length`, lines 127–131). Done pill: `AnimatedPressable`, `height: 36`, `borderRadius: 18`, `paddingHorizontal: 16`, `backgroundColor: palette.colors.accent`, text "Done" in `Nunito_700Bold` 15 white, `accessibilityRole="button"`, `accessibilityLabel="Done editing"`. When not editing, the count badge renders exactly as today.
  - **Empty-space tap:** set `contentContainerStyle` to include `flexGrow: 1`, and render `ListFooterComponent` as a `Pressable` with `style={{ flexGrow: 1, minHeight: 80 }}` and `onPress={() => isEditing && setIsEditing(false)}` — taps in the space below the last row exit edit mode. (Taps between cards within a row are absorbed by the ScrollView; the footer region + Done are the exit surfaces. Do not add `onTouchStart` to the FlatList — it bubbles from card touches and would break badge taps.)
  - **Blur/unmount:** `useFocusEffect(useCallback(() => () => setIsEditing(false), []))` (from `expo-router`) — leaving the tab or navigating away exits edit mode.
  - **Last story deleted:** `useEffect` — if `isEditing && stories.length === 0`, `setIsEditing(false)`.
- **Card tap while editing:** `StoryCard` receives `editMode` and makes body press a no-op (§3); `handleStoryPress` unchanged.
- `renderItem` passes new props: `editMode={isEditing}`, `onDeletePress={handleDeleteRequest}`, `jigglePhaseIndex={index}` (use the `renderItem` `index` argument), and includes `isEditing` in the `useCallback` deps. `FlatList` gets `extraData={isEditing}`.

### 2. Confirm + optimistic delete — `mobile/app/(tabs)/index.tsx`

- New `handleDeleteRequest(story: Story)`: computes `displayTitle = story.title?.trim() || `Story for ${story.childName}``, then `Alert.alert('Delete this story?', `"${displayTitle}" will be permanently removed.`, [{ text: 'Cancel', style: 'cancel' }, { text: 'Delete', style: 'destructive', onPress: () => { Haptics.impactAsync(Light); deleteMutation.mutate(story.id); } }])`.
- `deleteMutation` gains **optimistic removal** (today it only invalidates on success, lines 58–65): `onMutate: async (id) => { await queryClient.cancelQueries({ queryKey: ['stories'] }); const previous = queryClient.getQueryData<Story[]>(['stories']); queryClient.setQueryData<Story[]>(['stories'], (old) => (old ?? []).filter((s) => s.id !== id)); return { previous }; }`; `onError: (error, _id, ctx) => { if (ctx?.previous) queryClient.setQueryData(['stories'], ctx.previous); Alert.alert('Error', …existing message…); }`; `onSettled: () => queryClient.invalidateQueries({ queryKey: ['stories'] })`. Remove the old `onSuccess`.

### 3. Jiggle + badge — `mobile/components/StoryCard.tsx`

- Props change: `interface StoryCardProps { story; onPress; onLongPress?; editMode?: boolean; onDeletePress?: (story: Story) => void; jigglePhaseIndex?: number; style? }` (new props optional with defaults `false` / `undefined` / `0` so other call sites, if any, compile unchanged).
- Wrap the existing `AnimatedPressable` card in an outer `Animated.View` (Reanimated). **The badge must live on this outer wrapper, not inside the card** — `styles.card` has `overflow: 'hidden'` (line 105), which would clip a corner-overlapping badge.
- **Jiggle:** `const rotation = useSharedValue(0); const reducedMotion = useReducedMotion();` (both from `react-native-reanimated`). In a `useEffect` on `[editMode, reducedMotion]`: if `editMode && !reducedMotion` → `rotation.value = withDelay((jigglePhaseIndex % 4) * 60, withRepeat(withSequence(withTiming(-1.5, { duration: 120, easing: Easing.inOut(Easing.quad) }), withTiming(1.5, { duration: 120, easing: Easing.inOut(Easing.quad) })), -1, true));` else → `cancelAnimation(rotation); rotation.value = withTiming(0, { duration: 100 });`. Animated style: `transform: [{ rotate: `${rotation.value}deg` }]`. Reduced motion ⇒ no jiggle, badge still renders.
- **Delete badge** (rendered only when `editMode`): absolutely positioned `top: -6, left: -6` on the outer wrapper (top-LEFT, overlapping the corner iOS-style); a 24×24 filled circle (`borderRadius: 12`, `backgroundColor: palette.colors.accent`, subtle shadow) containing `<Ionicons name="remove" size={18} color="#fff" />`; wrapped in a `Pressable` with `hitSlop={10}`, `onPress={() => onDeletePress?.(story)}`, `accessibilityRole="button"`, `accessibilityLabel={`Delete ${displayTitle}`}` (reuse the `displayTitle` already computed at line 27).
- **Body press in edit mode:** `onPress={editMode ? undefined : () => onPress(story)}` — tapping the card body while editing does nothing (does not exit edit mode, does not open the reader). `onLongPress` stays wired (parent decides; entering edit mode again is a no-op).
- **Screen-reader delete, always available:** on the `AnimatedPressable`, add `accessibilityActions={[{ name: 'delete', label: 'Delete story' }]}` and `onAccessibilityAction={(e) => { if (e.nativeEvent.actionName === 'delete') onDeletePress?.(story); }}` — present in **both** modes, so VoiceOver users reach the same confirm flow without long-press or edit mode. This replaces the old long-press-delete path entirely.

### 4. Old path removal

The old `handleStoryLongPress` delete-`Alert` (index.tsx lines 81–94) is fully replaced by §1's enter-edit-mode handler. No direct-delete-on-long-press remains anywhere.

### 5. Haptics dependency — `mobile/package.json`

`expo-haptics` is **not currently a dependency** (verified 2026-07-05). Add it with `cd mobile && npx expo install expo-haptics` (pins the SDK-matched version), then **regenerate `package-lock.json` under npm 10** per [AUTONOMOUS_EXECUTION.md](AUTONOMOUS_EXECUTION.md) §1 (EAS builder runs npm 10). Import it **lazily inside the handlers** (`const Haptics = require('expo-haptics')` in a `try/catch`, same pattern as the FC-029 social-sign-in native modules) so an existing dev client built without the module degrades to no-haptics instead of crashing; full haptics arrive with the next EAS build.

## Risks & mitigations

- **Badge clipped by `overflow: 'hidden'`** on `styles.card`. Mitigation: badge lives on the new outer wrapper (§3), which has default `overflow: visible`; card clipping is untouched.
- **Continuous jiggle costs CPU/battery on large grids.** ±1.5° `withRepeat` transforms run on the UI thread (cheap), stop the moment edit mode exits (`cancelAnimation`), and exit on blur — bounded exposure. If profiling shows jank on iPad-sized grids, drop stagger buckets from 4 to 2.
- **Optimistic removal vs. the FC-031 15s `refetchInterval`.** A poll landing between `onMutate` and server commit could resurrect the row. Mitigated by `cancelQueries` in `onMutate` + `invalidateQueries` in `onSettled`; the confirm step also keeps the window short. Verify in the manual pass (delete while another story is generating).
- **`expo-haptics` missing from the current dev client / TestFlight build 13.** Lazy `require` + `try/catch` (§5) degrades to silent no-haptics; next EAS build restores it.
- **Merge conflict with FC-038** (also edits `StoryCard.tsx`). This plan is **Wave B**: execute only after FC-038 merges, branching from updated `origin/main`. Lockfile also overlaps FC-024 (test runner adds mobile deps) — whoever lands second regenerates the lockfile on top of merged main, under npm 10.
