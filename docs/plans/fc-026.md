## Context

On an iPhone 17 Pro Max two screens render wrong because layout is hardcoded to one form factor:

1. **Library in landscape is unusable** — it "zooms into" just the first two stories. Root cause: `mobile/app/(tabs)/index.tsx` hardcodes `numColumns={2}` with `flex: 1` cells whose `StoryCard` cover is `aspectRatio: 3/4`. When the row width ~doubles in landscape (or on iPad), each of the two cards becomes ~2× wider → ~2× taller, so only the first row fits the now-shorter viewport.

2. **Reader clips baked-in words** — story narration is baked *into* each illustration (FC-020), and `mobile/components/PageCurl/Curl.tsx` draws every image `fit="cover"`, which crops the edges. Because landscape device aspect ratios span ~1.33:1 (iPad) to ~2.16:1 (Pro Max) and the backend (`backend/src/services/gemini.ts`) requests images with no pinned `aspectRatio`, the crop eats text on any device whose ratio differs from the generated image.

The broader goal — "render beautifully on the full array of Apple devices" — is **phased**. This plan ships the two correctness bugs plus the minimal foundation they need. iPad/landscape polish across the other screens is **FC-027**; an optional backend image-aspect pin is **FC-028**. One PR per FC.

## Goals

- Library grid adapts column count to available width on every iPhone/iPad and both orientations.
- Reader never clips baked-in narration text, on every device and every already-generated story.
- A minimal, reusable responsive primitive (`useResponsive` + root `SafeAreaProvider`) that FC-027 builds on.

## Non-goals

- iPad polish for login/register/settings/create (FC-027).
- Backend image aspect-ratio pin (FC-028).
- Font/spacing scaling beyond what the grid needs.

## Decisions locked with the user

- **Phasing:** bugs + foundational responsive layer now; iPad/all-screen polish as a separate follow-up FC.
- **Reader fit:** `fit="contain"` (guarantees no clipped text on every device *and* every existing baked image, which is frozen) with a **blurred ambient backdrop** filling the letterbox area so it reads full-bleed rather than black-barred. `cover` + a "text safe-margin" prompt was rejected: it can't fix existing stories and bets every future generation keeps text off the edges at ~90% layout reliability — reintroducing the bug.

## Proposed approach

### 1. Root SafeAreaProvider — `mobile/app/_layout.tsx`
Wrap the tree in `SafeAreaProvider` (from `react-native-safe-area-context`, already a dependency), inside `GestureHandlerRootView` and outside the query/theme providers. Makes the existing `useSafeAreaInsets()` consumers authoritative and rotation-correct.

### 2. New responsive hook — `mobile/hooks/useResponsive.ts`
Thin composition of `useWindowDimensions()` + `useSafeAreaInsets()`. No new deps, no context.

```ts
export type DeviceClass = 'phone' | 'tablet';
export interface Responsive {
  width: number; height: number;
  isLandscape: boolean;                 // width > height
  isTablet: boolean;                    // Math.min(width,height) >= 600
  gutter: number;                       // 20 phone / 32 tablet
  insets: EdgeInsets;
  gridColumns(target?, min?, max?): { columns: number; cellWidth: number; gap: number };
}
```
- `isTablet`: `Math.min(width, height) >= 600` — every iPhone < 600 on its short edge, every iPad ≥ 600; using `min` is orientation-stable.
- Extract the column math as a **pure exported function** `computeGrid(available, opts)` so it's unit-testable once a runner exists (FC-024).

### 3. Library reactive grid — `mobile/app/(tabs)/index.tsx`
```
GAP=14, TARGET=178, MIN_COLUMNS=2, MAX_COLUMNS=5
available = width - gutter*2 - insets.left - insets.right
columns   = clamp(floor((available + GAP)/(TARGET + GAP)), MIN, MAX)
cellWidth = (available - GAP*(columns-1)) / columns
```
- `key={`grid-${columns}`}` so the FlatList remounts cleanly when `numColumns` changes (RN requirement).
- `numColumns={columns}`; remove per-cell `flex:1` and the manual `marginLeft` gap; cell becomes fixed `width: cellWidth`.
- `columnWrapperStyle={{ gap: GAP, marginBottom: GAP }}`; drop `ItemSeparatorComponent`.
- `listContent` + header use `paddingLeft: gutter + insets.left`, `paddingRight: gutter + insets.right`.
- `StoryCard` unchanged (cover is `width:'100%', aspectRatio:3/4`).

### 4. Reader contain + blurred ambient backdrop — `mobile/components/PageCurl/Curl.tsx`
Replace both `fit="cover"` draws. Compose each page (static `nextImage`, and curling `currentImage`) as two layers so backdrop + foreground curl together:
1. **Backdrop:** same image `fit="cover"`, wrapped in a layer `Paint` with a `Blur` (~20–28 px), plus a semi-transparent black `Rect` to darken.
2. **Foreground:** same image `fit="contain"` (whole image, centered, never clipped).

Keep `imageRect = XYWHRect(0,0,width,height)`; `contain` centers automatically. Remove the stale cover-crop comment.

## Critical files

- `mobile/app/_layout.tsx` — root `SafeAreaProvider`
- `mobile/hooks/useResponsive.ts` — new hook + pure `computeGrid`
- `mobile/app/(tabs)/index.tsx` — reactive grid
- `mobile/components/PageCurl/Curl.tsx` — `contain` + blurred backdrop

## Reuse

- `useWindowDimensions` + `useSafeAreaInsets` (already used in `read.tsx`, `CustomTabBar.tsx`, library header) — composed by `useResponsive`.
- Existing Skia `Group`/`Paint`/`Blur` primitives already imported in the reader.

## Risks & mitigations

- **FlatList numColumns change throws** → mitigated by the `key={`grid-${columns}`}` remount.
- **Blurred backdrop GPU cost** (4 image draws + 2 blurs/frame) → acceptable on target devices; confirm 60fps on the curl during verification.
- **Adding root provider changes inset values** → verify tab-bar bottom padding and create-screen top padding unchanged on phones.
