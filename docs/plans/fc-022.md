## Context

In the full-page story reader ([mobile/app/story/[id]/read.tsx](../../mobile/app/story/[id]/read.tsx)), the "The End" card is rendered the moment the user reaches the last page:

```jsx
{isLastPage && (
  <Animated.View style={styles.endOverlay} ...>   // endOverlay = absoluteFill + rgba(0,0,0,0.6) scrim
    <View style={styles.endCard}> The End / Hope you enjoyed … / Back to Library </View>
  </Animated.View>
)}
```

`isLastPage = currentPage === pages.length - 1`. Because `endOverlay` is a full-screen dark scrim centered over the page, **the last story page is covered and cannot be read.** Reported by the user.

### How navigation works (constrains the fix)

The page-curl ([components/PageCurl/Curl.tsx](../../mobile/components/PageCurl/Curl.tsx)) only commits **forward**, and only when `currentPage < totalPages - 1` (`canCommitRef`, Curl.tsx:65). On the last page a forward swipe **springs back and emits no event**; tap-right is a no-op because `goToPage` clamps. So "the user scrolled past the last page" is not an event the Curl currently expresses — implementing an over-scroll trigger would mean inventing a new gesture callback and is undiscoverable (the page just springs back). Rejected in favor of a real page.

## Goals

- The last *story* page renders with no overlay and is fully readable.
- "The End" is a distinct page the user turns to via the normal page-curl.
- Confetti fires when the ending is reached (on the end page), not on the last story page.

## Non-goals

- No new gesture/over-scroll event in the Curl shader handler (the rejected Option 2).
- No backend / data-model change. The end page is a client-only synthetic page, exactly like the cover.
- No change to how content pages or the cover render.

## Proposed approach

Mirror the existing **cover synthesis** pattern. The reader already prepends a synthetic page 0 when `story.titlePageImageUrl` exists ([read.tsx:55-66](../../mobile/app/story/[id]/read.tsx#L55-L66)). Do the analogous thing at the tail: **append a synthetic, image-less "The End" page** whenever there is at least one content page.

In [read.tsx](../../mobile/app/story/[id]/read.tsx):

1. **Build the pages array** as `[...cover?, ...contentPages, endPage]`, where `endPage = { pageNumber: -1, text: '', imageUrl: '' }`. Only append `endPage` when `contentPages.length > 0` (guards the empty/loading case). Track `hasEndPage`.
2. **Derive `isEndPage = hasEndPage && currentPage === pages.length - 1`.** This replaces the old `isLastPage` as the trigger for the card + confetti.
3. **Counter / dots math.** With an extra trailing page, the page counter denominator must exclude both the cover and the end page. Compute `coverCount = hasCover ? 1 : 0`, `storyPageCount = pages.length - coverCount - (hasEndPage ? 1 : 0)`. Counter label: `isEndPage ? 'The End' : (hasCover && currentPage === 0 ? 'Cover' : `${currentPage - coverCount + 1} / ${storyPageCount}`)`. (The `currentPage - coverCount + 1` form is algebraically identical to today's `currentPage + (hasCover ? 0 : 1)`.) The end page gets a dot like the cover does.
4. **Confetti** fires on `isEndPage` (same `confettiFiredFor` ref guard).
5. **End card** renders only when `isEndPage`. Because the end page has no image, the Curl already paints it solid black (its base `<Rect color="black">`), so the heavy `rgba(0,0,0,0.6)` scrim is no longer needed — set `endOverlay` background transparent so the card sits on the clean black end page. Keep the `FadeIn.delay(600)` so the card appears after the curl settles.

In [components/PageCurl/usePageImages.ts](../../mobile/components/PageCurl/usePageImages.ts):

6. **Coerce empty image URLs to `null`** (`|| null` instead of `?? null`, and the same for the prev/next ternaries) so the synthetic end page's `imageUrl: ''` never reaches Skia's `useImage('')`. Result: `current`/`next` are `null` for the end page and the Curl renders its black base Rect. Defensive for any malformed page too.

No change to `Curl.tsx`: it is already `null`-safe for `currentImage`/`nextImage`, and forward-commit from the last story page works automatically once `totalPages` grows by one.

## Critical files

- `mobile/app/story/[id]/read.tsx` — pages synthesis (append end page), `isEndPage`, counter/dots math, confetti trigger, end-card render condition, `endOverlay` style (drop scrim).
- `mobile/components/PageCurl/usePageImages.ts` — empty-URL → null coercion so the image-less end page loads no image.

## Reuse

- The cover-synthesis pattern in `read.tsx` (`hasCover` / page-0 prepend) — the end page is the symmetric tail version.
- `Curl.tsx` forward-commit + null-image rendering — unchanged, reused as-is.
- Existing `ConfettiCannon`, `endCard` / `endButton` styles, `confettiFiredFor` ref.

## Risks & mitigations

- **Risk:** `useImage('')` could attempt a bad load / log a warning.
  - Mitigation: the `|| null` coercion in step 6 ensures the end page passes `null` to `useImage`, the documented "no image" path.
- **Risk:** Counter/dot math off-by-one (cover + end both offset it).
  - Mitigation: explicit `coverCount` / `hasEndPage` terms; verify all four combinations (±cover × on/at end) read correctly. Unit-test the label helper (below).
- **Risk:** Forward-swipe from last story page to end page doesn't commit.
  - Mitigation: `canCommitRef = currentPage < totalPages - 1` is satisfied for the last story page once the end page is appended (its index is `totalPages - 2 < totalPages - 1`). Confirmed by reading Curl.tsx.
- **Risk:** Backward navigation from the end page.
  - Mitigation: tap-left → `goToPage(currentPage - 1)` already returns to the last story page; no special handling needed.
