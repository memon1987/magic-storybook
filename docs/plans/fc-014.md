## Context

A "writing style" wizard step (Dr. Seuss / Eric Carle / etc.) existed in the original create form but was silently dropped during the FC-001 frontend redesign. The backend `StoryInput.authorStyle` field still exists and is actively consumed by `buildStoryPrompt` at [backend/src/prompts/story.ts:34-36](../../backend/src/prompts/story.ts#L34-L36): if `authorStyle` is set, the prompt asks the LLM to write "in the style of ${authorStyle}". Since the wizard no longer sends the field, every story currently falls back to the same default voice. Stories feel samey.

This is one of four story-generation improvements approved on 2026-05-11 (see `~/.claude/plans/lets-pick-back-up-warm-map.md` for the full overhaul plan and the v1 → v2 → v3 revision history). FC-014-lite is the first to ship: smallest scope, lowest risk, no dependencies on the other three, immediate user-visible win.

## Goals

- Restore a writing-style step to the create wizard
- 3 distinct voices, distinguishable in the resulting prose
- No copyrighted author names in the LLM prompt (use structural descriptors only)
- No copyrighted author names in UI labels either (per user, 2026-04-28)
- Stories created without the new field still generate (no regression for older clients or pre-FC-014 saved drafts)

## Non-goals

- 6+ voices. Start at 3; expand later if usage shows demand.
- Few-shot writing-sample anchors. v1 of the parent plan proposed this with a fabricated benchmark; v3 drops it. If 3-voice inline structural descriptors don't produce distinguishable voices in practice, **then** revisit.
- A separate profile data file. Inline the structural descriptors directly in `story.ts`. Promote to a separate file only if voices grow beyond ~5.
- Author-style metadata surfaced on the library card or reader UI. The voice picker is generation-only.

## Proposed approach

### Backend

In `backend/src/prompts/story.ts`:

- Introduce a typed `WritingStyleId = 'bouncy-rhymes' | 'gentle-refrains' | 'sweet-simple'`
- Replace the current `authorStyle`-driven `styleGuide` block (lines 34-36) with a lookup against an inline `WRITING_STYLE_DESCRIPTORS` map. Keys are the WritingStyleId values; values are 3-5 line structural directives (meter, rhyme scheme, vocabulary level, signature traits). No author names.
- Continue supporting the existing `authorStyle` free-text fallback for backwards compatibility — older clients sending free-text `authorStyle` still get the same behavior they had before. New `writingStyle` field takes precedence when both are present.
- Default block (no style provided) stays as today's warm-and-gentle fallback.

In `backend/src/types/index.ts`:

- Add `writingStyle?: WritingStyleId` to `StoryInput`
- Export `WritingStyleId` for the route's validator + the story prompt module

In `backend/src/routes/stories.ts`:

- Validate `writingStyle` is one of the 3 known ids (or absent)
- Mirror today's pass-through to `generateStory(input)`

### Mobile

In `mobile/services/api.ts`:

- Add `writingStyle?: 'bouncy-rhymes' | 'gentle-refrains' | 'sweet-simple'` to `StoryInput`
- Export a `WRITING_STYLES` array of `{ id, label, description }` for the wizard to consume (no structural descriptors here — those live on the backend; client only needs labels)

In `mobile/app/(tabs)/create.tsx`:

- Add a writing-style step between "Moral" (step 3) and "Story length" (step 4). New `TOTAL_STEPS = 7`.
- Mirror the existing **chip-row pattern** ([create.tsx:324-349](../../mobile/app/(tabs)/create.tsx#L324-L349)) since 3 options fit cleanly horizontally — no need for the 3-column grid we'd use for 6+ options.
- Step title: "Pick a writing style". Suggestion chips: "Bouncy Rhymes", "Gentle Refrains", "Sweet & Simple". Sub-label below each (e.g. "Rhyming and energetic" for Bouncy Rhymes) — implement as a small dictionary keyed by id and rendered in the chip body.
- `FormData` gets `writingStyle: WritingStyleId` (default `'gentle-refrains'`).
- `canContinue` returns `true` for this step regardless of selection (a default is always set).

### Voice descriptors (committed verbatim to backend)

| id | UI label | Structural directive (backend prompt insert) |
|---|---|---|
| `bouncy-rhymes` | Bouncy Rhymes | "Write in rhyming couplets with an energetic, anapestic-leaning rhythm. Use AABB rhyme scheme. Repeat key phrases for emphasis. Sprinkle in exclamations. Keep vocabulary at kindergarten level with punchy single-syllable words where possible." |
| `gentle-refrains` | Gentle Refrains | "Write with repetitive refrains and sensory adjectives. Use a day-by-day or step-by-step progression. Each page should echo a phrase from the previous page. Vocabulary is simple, soft, and concrete. Avoid sharp consonants where possible — favor flowing word sounds." |
| `sweet-simple` | Sweet & Simple | "Write in very short sentences — 3 to 7 words each. Use questions to engage the child. Include sound words and onomatopoeia. Convey big emotions through simple words. Use lots of repetition and direct address (you, your, my)." |

These three are deliberately structurally distinct (rhyme vs refrain vs short-sentence) so a reader can tell them apart in a single page of output.

## Reuse

- Existing `TextStep` component pattern in `create.tsx` for chip-row suggestion display
- Existing wizard step transition animations (Reanimated `SlideInRight` / `SlideOutLeft`)
- Existing default-voice fallback in `story.ts` for stories generated without a style
- `authorStyle` free-text fallback retained for backwards compat (no breaking change to old clients)

## Risks & mitigations

- **Risk:** Three voices may not be distinguishable enough in actual generated output (Gemini Flash text model might smooth them all toward a default tone).
  - **Mitigation:** Verification step requires reading actual output side-by-side. If voices read the same, iterate the descriptors (sharpen the distinctions). Worst case, we conclude few-shot anchors are needed after all and that becomes FC-014-v2.

- **Risk:** Older saved-draft wizards (if any in-flight on a user's phone) may submit without the new field.
  - **Mitigation:** `writingStyle` is optional on `StoryInput`; backend falls back to the existing default block. No breaking change.

- **Risk:** The wizard now has 7 steps. Adds friction.
  - **Mitigation:** Step 7 has a sensible default (`gentle-refrains`) and `canContinue` is always true — the step can be tapped-through without changing anything. Users who care get the choice; users who don't get a reasonable default.

- **Risk:** Adding a step shifts `length` from step 4 to 5 and `artStyle` from 5 to 6. Anything else in the wizard tied to step numbers?
  - **Mitigation:** Confirmed by reading [create.tsx:128-144](../../mobile/app/(tabs)/create.tsx#L128-L144) — `canContinue` switches on `stepIndex` but each case is independent; renumbering is safe. `progress` is computed from `(stepIndex + 1) / TOTAL_STEPS` — auto-adjusts. No other hardcoded step indices.
