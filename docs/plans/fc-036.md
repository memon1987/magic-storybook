## Context

Story generation takes ~2–5 minutes. [`mobile/app/story/[id]/generating.tsx`](../../mobile/app/story/[id]/generating.tsx) currently renders an `ActivityIndicator` + `progress.message` + a raw `completedSteps of totalSteps` line — honest but joyless, and the per-phase step counter resets between phases so it *feels* like the bar restarts. The FC-017 worker already streams rich real state into the Firestore story doc, which the screen subscribes to via `subscribeToStory` ([`mobile/services/stories.ts`](../../mobile/services/stories.ts)). This FC replaces the in-progress state with a playful **determinate** progress bar driven by those real signals, time-smoothed between milestones.

### The real Firestore signal (enumerated from code — do not invent fields)

Written by [`backend/src/services/worker.ts`](../../backend/src/services/worker.ts) (`FirestoreJobStateWriter`), [`backend/src/services/gemini.ts`](../../backend/src/services/gemini.ts), and [`backend/src/routes/stories.ts`](../../backend/src/routes/stories.ts):

- `status`: `'queued' | 'generating' | 'complete' | 'failed'`.
- `progress.phase` / `progress.completedSteps` / `progress.totalSteps` / `progress.message` / `progress.updatedAt` — via `saveProgress` (dot-notation per key). The `GenerationPhase` union is `'queued' | 'story-text' | 'char-refs' | 'cast' | 'title' | 'anchor-pages' | 'parallel-pages' | 'finalizing'`, **but only these are ever actually written**: `'queued'` (route, initial `set()` at stories.ts:270), `'story-text'` (worker.ts:362/365, steps 0→1 of 1), `'char-refs'` (gemini.ts:848/906, per-ref ticks), `'anchor-pages'` (gemini.ts:1006/1023/1049), `'parallel-pages'` (gemini.ts:1061/1091), `'finalizing'` (worker.ts:382). **`'cast'` and `'title'` exist in the type but no `saveProgress` call emits them.**
- Cast/title completion is instead observable via doc fields: `castAttempted: true` (+ `castReferenceUrl`, null-URL possible on skip/failure — worker.ts `saveCastReference`) and `titleAttempted: true` (+ `titlePageImageUrl` — `saveTitlePage`).
- `pageUrls` — a **map** (not array), `Record<string, PageGenerationRecord>` keyed by `String(pageNumber)`, values `{url, ocrPassed, attempts}`; one key added per completed page via `savePage`. Deleted (with `progress`, `storyText`, `castAttempted`, `titleAttempted`) in the terminal `batch.commit` that also sets `status: 'complete'`.
- `attempt` — incremented by `claimLock` on every worker claim; `failureReason: FailureCode` on failure.
- Expected page count: backend `getPageCount` (`backend/src/prompts/story.ts:78`) — **short 4, medium 6, long 8** (the doc carries `length`).

`StorySnapshot` in `mobile/services/stories.ts` currently exposes only `id, status, title, progress, failureReason, attempt` — it must be extended (explicit fields, per its own "don't spread the raw doc" comment).

## Goals

- Determinate, honest progress bar that advances through the whole 2–5 min run without visible stalls >~20s or backward movement — including across Resume attempts.
- Friendly, phase-accurate captions using `childName` ("Dreaming up Mira's story…", "Painting page 3 of 6…").
- Gentle looping micro-animation; full reduced-motion fallback.
- FC-031 failed/Resume/retry-budget/safety_blocked states preserved byte-for-byte in behavior.

## Non-goals

- No page thumbnails / illustration peeks (spoils the story before reading).
- No Skia, no Lottie, no new dependencies (Reanimated ~4.1.1 is already in `mobile/package.json`).
- No backend changes — the worker's progress contract is consumed as-is.
- No changes to the complete-navigation logic (`navigatedForAttemptRef`), subscription lifecycle, or the library's status rows.

## Proposed approach

### 1. Pure progress model — new file `mobile/utils/storyProgress.ts`

(New `mobile/utils/` directory — deliberately NOT inside `mobile/app/`, because Expo Router treats files under `app/` as route candidates and warns on non-route modules.)

Exported pure function, no imports from React/Reanimated:

```ts
computeStoryProgress(doc: ProgressDocInput, expectedPages: number, elapsedInPhaseMs: number)
  → { fraction: number; label: string; milestoneKey: string }
```

`ProgressDocInput` = the subset of `StorySnapshot` it reads: `status`, `progress` (phase/completedSteps/totalSteps), `childName`, `castAttempted`, `titleAttempted`, `pageUrlsCount`, `attempt`.

**Milestone bands (weights calibrated to the FC-016 finding that char-refs dominate latency):**

| Band | Fraction range | Real signal that fills it |
|---|---|---|
| queued | 0 → 0.05 | `progress.phase === 'queued'` (or missing/malformed progress → floor 0.05) |
| story-text | 0.05 → 0.15 | `phase === 'story-text'`; sub-fraction `completedSteps/totalSteps` |
| char-refs | 0.15 → 0.55 | `phase === 'char-refs'`; sub-fraction `completedSteps/totalSteps` |
| cast + title | 0.55 → 0.70 | `castAttempted` fills 0.55→0.625; `titleAttempted` fills 0.625→0.70 (flags, NOT phase — see Context) |
| pages | 0.70 → 0.98 | `0.70 + 0.28 × (pageUrlsCount / expectedPages)` — split evenly per page as `pageUrls` keys land (spans both `anchor-pages` and `parallel-pages` phases) |
| finalize | 0.98 → 1.0 | `phase === 'finalizing'` → 0.98; `status === 'complete'` → 1.0 |

(The FC entry's "queued 0→0.05, char refs 0.05→0.55" band is subdivided 0.05/0.15 to account for the real `'story-text'` phase between them; char-refs keeps the dominant share.)

**Time smoothing:** within the current band, the *real* sub-fraction gives a base `b`; the displayed fraction creeps asymptotically toward the next real boundary `n` (the fraction the NEXT real signal would jump to): `fraction = b + (n − b) × (1 − e^(−elapsedInPhaseMs / τ))`, which never reaches `n`. Per-band τ constants (ms, exported for tests, tunable): queued 15_000, story-text 30_000, char-refs 90_000 (per-ref gap; FC-016: char-refs ≈332s of 440s), cast/title 25_000, per-page 20_000, finalizing 10_000. When the real signal lands, the base jumps to the boundary — no rubber-banding because the creep never got there.

**Monotonicity is the caller's clamp** (the pure function is stateless): the screen keeps `maxFractionRef` and displays `Math.max(maxFractionRef.current, fraction)` — this also covers Resume (`attempt` increments, phases rewind → raw fraction may drop → bar holds the max reached). Also export `clampMonotonic(prev, next)` so the invariant is unit-testable.

**Labels** (derived from real fields; fallback `progress.message`, final fallback `'Starting…'`): queued → "Warming up the crayons…"; story-text → "Dreaming up {childName}'s story…"; char-refs → "Drawing {childName} and friends… ({completedSteps} of {totalSteps})"; cast/title band → "Painting the cover…"; pages → "Painting page {min(pageUrlsCount+1, expectedPages)} of {expectedPages}…"; finalizing → "Sprinkling the final magic…". Malformed/unknown doc → `{fraction: 0.05, label: 'Starting…'}`.

`milestoneKey` = a string of the concatenated real signals (phase|completedSteps|castAttempted|titleAttempted|pageUrlsCount|attempt) — the screen resets its `elapsedInPhaseMs` timer whenever it changes.

### 2. Subscription surface — `mobile/services/stories.ts`

Extend `StorySnapshot` with explicit fields (keep the no-raw-spread rule): `childName?: string`, `length?: 'short' | 'medium' | 'long'`, `castAttempted?: boolean`, `titleAttempted?: boolean`, `pageUrlsCount?: number` (computed in the service as `Object.keys(data.pageUrls ?? {}).length` — page URLs themselves never cross into the UI, reinforcing no-spoilers). Map each in the existing `onSnapshot` handler. `expectedPages` on the screen = `{short: 4, medium: 6, long: 8}[length] ?? 6` (mobile mirror of backend `getPageCount`; constant lives in `storyProgress.ts`).

### 3. Screen — `mobile/app/story/[id]/generating.tsx` (in-progress branch ONLY)

Replace the `ActivityIndicator` + fraction text in the `status === 'queued' || 'generating'` branch with:

- **Determinate bar:** a track `View` + fill `Animated.View` whose width is a Reanimated shared value; on each recompute, `progressSV.value = withTiming(clamped, {duration: 400})`.
- **Tick loop:** a single `setInterval` (500ms) recomputes `computeStoryProgress(latestSnapshotRef.current, expectedPages, Date.now() − phaseStartedAtRef.current)` and writes **only** `progressSV.value` — no React state per tick (no re-render storm; snapshot events remain the only `setState` source). Label + milestoneKey update on snapshot events. Interval cleared on unmount and when leaving the in-progress branch.
- **Captions:** the computed `label` in the existing card title slot (existing card styles/palette), crossfaded via the already-imported `FadeIn`/`FadeOut` keyed by label.
- **Micro-animation:** 3 `Ionicons` (`star`, `sparkles`, `book`) above the bar on a gentle staggered `withRepeat(withSequence(...))` translateY bounce (Reanimated only).
- **Reduced motion:** `useReducedMotion()` from `react-native-reanimated` → no tick interval, no bounce loop, no `withTiming` (set bar width directly on snapshot events), static captions. Fractions then update only on real milestones — still determinate, just stepped.
- Keep: the "usually takes 2–5 minutes" hint, the Close→library affordance, the pre-subscription `!result` spinner, `GradientBackground` + `useTheme` palette usage, fonts already loaded in `_layout.tsx` (Nunito/Quicksand/Baloo 2).

**FC-031 conditionals to preserve verbatim (the executor greps for these before opening the PR):** `MAX_RESUME_ATTEMPTS = 3`; `navigatedForAttemptRef` keyed on `next.attempt ?? 0`; the `'error' in result` branch; the `result.status === 'failed'` branch including `budgetExhausted = attempt >= MAX_RESUME_ATTEMPTS`, `suppressResume = code === 'safety_blocked' || budgetExhausted`, the `INPUT_RELATED`/`isInputRelated` headline branching, the `onCreateNew` "Create a new story" CTA, `onResume`/`isResuming`/`resumeError`, and "Back to library".

## Risks & mitigations

- **Bar stalls in the long char-ref band** (FC-016: ~332s of a ~440s run). Mitigation: char-refs gets the widest band (0.15→0.55), per-ref ticks land as real jumps, and the τ=90s asymptotic creep keeps visible motion between ticks.
- **Backward jumps on Resume or phase re-runs.** Mitigation: `clampMonotonic` + `maxFractionRef`; attempt is part of `milestoneKey` so the elapsed timer resets rather than fast-forwarding the creep.
- **Re-render storm** (500ms tick × Firestore snapshots). Mitigation: tick writes only the shared value; React state changes only on snapshot events; reviewer persona 1 targets exactly this.
- **`pageUrls`/`progress` vanish at completion** (terminal batch deletes them). Harmless: the same commit sets `status='complete'`, the existing navigation effect fires; the clamp prevents any dying-frame regression.
- **Dishonest bar** (creep implies work that isn't happening). Mitigation: creep is bounded by the *next real boundary* and asymptotic — it can never claim a milestone that hasn't landed; reviewer persona 2 judges this.

## Verification

Unit-test spec for `computeStoryProgress` (executable now only if FC-024's runner has landed; otherwise this table ships as the contract and tests follow FC-024):

| Case | Input | Expected |
|---|---|---|
| Malformed doc | `progress` missing / unknown phase | `{fraction: 0.05, label: 'Starting…'}` |
| Queued floor | `phase='queued'`, elapsed 0 | fraction ≥ 0 and < 0.05 |
| Char-ref ticks | `char-refs` 2 of 4 done | base 0.15 + 0.4×(2/4) = 0.35; creep < next tick boundary |
| Asymptote never crosses | any band, elapsed → ∞ | fraction strictly < next boundary |
| Cast/title flags | `castAttempted` only → ≥0.55, <0.70; both flags | ≥ 0.625 / crosses 0.70 only with pages |
| Page increments | `pageUrlsCount` 3 of 6 expected | 0.70 + 0.28×(3/6) = 0.84 |
| Finalize / complete | `phase='finalizing'` / `status='complete'` | 0.98 creeping <1.0 / exactly 1.0 |
| Monotonicity | scripted snapshot sequence incl. an out-of-order regression | `clampMonotonic` never decreases |
| Resume hold | fraction 0.84, then `attempt`+1 with early-phase doc | displayed stays 0.84 |
