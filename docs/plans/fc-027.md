## Context

FC-026 (Done, PR #28, shipped in EAS builds 11/13) fixed the two device-layout *bugs* — library landscape zoom and reader text clipping — and laid the responsive foundation: a root `SafeAreaProvider`, [`mobile/hooks/useResponsive.ts`](../../mobile/hooks/useResponsive.ts) (already exposes `width/height`, `isLandscape`, `deviceClass`, `isTablet`, `gutter`, `insets`, `gridColumns`, plus the pure exported `computeGrid`), and a reactive library grid in `mobile/app/(tabs)/index.tsx`. The rest of the app still assumes a phone form factor on iPad:

- **Auth screens** ([`mobile/app/(auth)/login.tsx`](../../mobile/app/(auth)/login.tsx), [`register.tsx`](../../mobile/app/(auth)/register.tsx)): the `SectionCard` is `width: '100%'` inside a 24pt-padded scroll — on an iPad Pro 12.9 the form card stretches to ~980pt wide with 56pt-tall inputs, which reads broken.
- **Settings** ([`mobile/app/(tabs)/settings.tsx`](../../mobile/app/(tabs)/settings.tsx)): every section card / row stretches edge-to-edge across the full 20pt-padded width.
- **Create wizard** ([`mobile/app/(tabs)/create.tsx`](../../mobile/app/(tabs)/create.tsx)): the art-style grid hardcodes `styleCard { width: '31%' }` (line 639) with `justifyContent: 'space-between'` — a 3-up phone assumption that yields comically large ~300pt cells on iPad. Length/writing-style cards and the footer CTA also span full width.

Two items from the original FC-027 entry are **stale or reassigned** (see Non-goals): the `'70%'` generating overlay no longer exists in `create.tsx` (the `GeneratingOverlay` component was deleted by FC-017 Phase 3; the dedicated `/story/[id]/generating` screen already caps its content at `maxWidth: 420` and is owned by FC-036), and reader-bar notch gutters are delivered by FC-040.

`useResponsive` deferred `scale` and `contentMaxWidth` to this FC (see the hook's header comment). This plan completes them and applies them to the three screen groups above.

## Goals

- Auth forms, settings sections, and create-wizard content are centered and capped at a readable width (560pt content box) on iPad, both orientations.
- Art-style grid renders 3-up on phones (pixel-comparable to today) and 4-up on tablets, with gap-aware computed cell widths instead of `width: '31%'`.
- `useResponsive` finishes its FC-026-deferred surface: `scale` (moderate tablet type/size scaling, clamped 1.0–1.25) and `contentMaxWidth` (560), both derived by pure exported helpers.
- Phones render **unchanged** — every new behavior is a no-op below the tablet breakpoint (`scale = 1.0`; `maxWidth` never binds under ~608pt).

## Non-goals

- **`mobile/app/story/[id]/read.tsx` — zero changes.** Reader top/bottom-bar safe-area gutters are FC-040's §5 (✕ reposition + inset padding). Touching `read.tsx` here would guarantee a merge conflict.
- **`mobile/app/story/[id]/generating.tsx` — zero changes.** FC-036 owns that file (see the conflict matrix in [AUTONOMOUS_EXECUTION.md](AUTONOMOUS_EXECUTION.md) §6). Its content column is already `maxWidth: 420`; any further tablet polish there ships with FC-036 or not at all. The FC entry's "'70%' generating overlay" item is dropped as stale.
- Library (`mobile/app/(tabs)/index.tsx`) — already responsive via FC-026; reference implementation only.
- Font-scale application beyond the specific spots listed in §4; app-wide typography scaling is future work.
- New dependencies. None are needed.

## Proposed approach

### 1. Extend `useResponsive` — `mobile/hooks/useResponsive.ts`

Add the two fields FC-026 deferred, each backed by a pure exported helper (unit-testable without a renderer, same pattern as `computeGrid`):

- `export const CONTENT_MAX_WIDTH = 560;` and `contentMaxWidth: number` on the `Responsive` interface — constant for now, but surfaced via the hook so a future per-class value is a one-line change.
- `export function computeScale(shortEdge: number): number` — returns `1.0` when `shortEdge < 600` (all phones), else linear `1 + ((shortEdge - 600) / (1024 - 600)) * 0.25` clamped to `[1.0, 1.25]`. iPad mini (744pt short edge) → ~1.085; iPad Pro 12.9 (1024pt) → 1.25. Hook exposes `scale: number` computed from `Math.min(width, height)` (orientation-stable, same convention as `isTablet`).
- `deviceClass` already exists — no change, but FC-027 is where consumers start using it.

### 2. New `ResponsiveContainer` — `mobile/components/ResponsiveContainer.tsx` (new file)

Small dumb component, no context, no new deps:

```tsx
export function ResponsiveContainer({ children, padding = 0, style }: {
  children: React.ReactNode; padding?: number; style?: StyleProp<ViewStyle>;
}) {
  const { contentMaxWidth } = useResponsive();
  return (
    <View style={[{ width: '100%', maxWidth: contentMaxWidth + padding * 2,
      alignSelf: 'center', paddingHorizontal: padding }, style]}>
      {children}
    </View>
  );
}
```

`maxWidth = contentMaxWidth + padding*2` keeps the *content box* at 560 while the container owns the horizontal padding. Host screens **move** their existing `paddingHorizontal` into the `padding` prop (never both, or padding doubles).

### 3. Apply to auth + settings

- **`login.tsx` / `register.tsx`:** remove `paddingHorizontal: 24` from `styles.scroll`; wrap everything inside the `ScrollView` in `<ResponsiveContainer padding={24}>` (keep `alignItems: 'center'` behavior — the container centers itself; inner items keep their current styles). `styles.card` stays `width: '100%'` — now 100% of ≤560. Scale application: `iconCircle` size and `title` fontSize multiply by `scale` (inline style override; phone = ×1.0 = today).
- **`settings.tsx`:** remove `paddingHorizontal: 20` from `styles.scroll`; wrap the scroll children (title, profile card, three `Section`s, logout button) in `<ResponsiveContainer padding={20}>`. Row/section internals untouched.

### 4. Create wizard — `mobile/app/(tabs)/create.tsx`

- Wrap the step content (children of the `Animated.View` step wrapper) and the footer's `AnimatedPressable` CTA each in `<ResponsiveContainer padding={24}>`, removing `paddingHorizontal: 24` from `styles.scroll` and `styles.footer`. The header row (back button + progress bar) stays full-width — a spanning progress affordance is conventional and keeps the diff small.
- **Art-style grid:** delete `styleCard.width: '31%'` and `styleGrid.justifyContent: 'space-between'`. In `ArtStyleStep`, compute: `columns = deviceClass === 'tablet' ? 4 : 3`; `const { cellWidth } = computeGrid(stepContentWidth, { gap: 12, min: columns, max: columns })` where `stepContentWidth = Math.min(width - insets.left - insets.right, contentMaxWidth + 48) - 48` (the ResponsiveContainer's inner width). Grid becomes `gap: 12` + `flexWrap` with per-card `width: cellWidth`. Forcing `min === max` reuses `computeGrid`'s gap-aware cell math while pinning the count — no new solver.
- Scale application: `stepTitle` fontSize/lineHeight and `bigInput` height multiply by `scale`. Nothing else.

## Reuse

- `computeGrid` (`mobile/hooks/useResponsive.ts`) — reused with `min === max` for the pinned-count art grid; do NOT write a second grid solver.
- `useResponsive` — single source for `deviceClass` / `scale` / `contentMaxWidth` / `insets`; no screen reads `Dimensions` directly.
- `mobile/app/(tabs)/index.tsx` — reference for the reactive-grid + gutter/insets pattern (do not modify).
- `SectionCard`, `GradientBackground`, `AnimatedPressable` — unchanged; they inherit the capped width from the container.

## Risks & mitigations

- **Phone regression from moved padding** (double-padding or lost padding when `paddingHorizontal` migrates into the container). Mitigation: per-screen rule in §2 — padding lives in exactly one place; phone checklist item explicitly diffs against today.
- **KeyboardAvoidingView + centered container on iPad** — a capped card centered in a wide screen can shift oddly when the keyboard animates. Mitigation: container is inside the ScrollView (layout-only, no new flex parents around KAV); verify keyboard behavior on iPad in the manual checklist.
- **`computeGrid` with `min === max` below its design width** — on the narrowest phones cellWidth ≈ (342 − 24)/3 ≈ 106pt vs today's ~106pt (`31%` of 342) — effectively identical, but verify SE explicitly.
- **FC-037 lands first and reshapes `create.tsx`** (it adds input validation UI there). Mitigation: Wave-B ordering (below); rebase on merged main before executing.
- **Scale creep** — `scale` invites sprinkling; this plan names the only five scaled properties (auth icon+title, create title/lineHeight+input height). Reviewers should flag any other usage.
