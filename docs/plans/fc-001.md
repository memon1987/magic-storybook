## Context

The current mobile app has a functional but basic UI built directly in screen files with no shared components. A complete redesign was done in Figma Make and exported as a web prototype (repo: `memon1987/Aistorybookappfrontendfigma`). The goal is to rebuild every screen in the existing Expo React Native app to match the new Figma designs.

This is a **clean rewrite** of all screens and styling — not an incremental migration. Old UI code is fully replaced, not patched.

## Goals

- Match all screens pixel-for-pixel to the new Figma designs
- Implement 6 switchable color palettes with persistence
- Add Typeform-style 6-step story creation wizard
- Add animated splash screen, custom tab bar, and landscape story reader
- Build a reusable component library in `mobile/components/`
- Replace all Framer Motion animations with react-native-reanimated equivalents

## Non-goals

- Backend changes — API, Firestore schema, and Cloud Run deployment are untouched
- Auth logic changes — Firebase Auth flow stays the same
- Data fetching changes — React Query patterns stay the same
- Android-specific optimizations (iOS-first, Android parity later)

## Proposed approach

8-phase clean rewrite. Each phase builds on the previous without breaking the app at intermediate points. Full details below.

### What stays (untouched)
- `mobile/services/api.ts` — API client with axios + Firebase token interceptor
- `mobile/services/firebase.ts` — Firebase Auth SDK init
- `mobile/hooks/useAuth.ts` — Auth context (login, register, logout, user state)
- `mobile/app/_layout.tsx` — Root layout structure (modified, not replaced)
- expo-router file-based routing structure
- React Query for data fetching

### What gets deleted
- `mobile/constants/Colors.ts` — Replaced entirely by new palette system
- `mobile/constants/Typography.ts` — Replaced by inline font references matching new design
- `mobile/app/story/[id]/preview.tsx` — Not in new Figma designs (story opens directly to reader)
- All old screen code — each file is fully rewritten, not patched

### What gets created new (11 files)
- `mobile/constants/ColorPalettes.ts` — 6 theme palettes
- `mobile/contexts/ThemeContext.tsx` — Theme provider with AsyncStorage persistence
- `mobile/components/AnimatedPressable.tsx`
- `mobile/components/GradientBackground.tsx`
- `mobile/components/ProgressBar.tsx`
- `mobile/components/StoryCard.tsx`
- `mobile/components/SectionCard.tsx`
- `mobile/components/CustomTabBar.tsx`
- `mobile/components/SplashScreenAnimated.tsx`
- `mobile/components/ThemeSelectorModal.tsx`
- `mobile/hooks/useAnimatedEntrance.ts`

### Deferred deletes
The originally-planned Phase 0 `rm` of `Colors.ts`, `Typography.ts`, and `story/[id]/preview.tsx` would break the build immediately — 8 screens import `Colors` and `_layout.tsx` routes to `preview`. Each file is now deleted in the phase that removes its last importer:
- `preview.tsx` + its `_layout.tsx` route entry → Phase 7 (story reader rewrite)
- `Colors.ts` + `Typography.ts` → Phase 8 (final cleanup, after all 8 importers are rewritten)

This keeps the app bootable across all intermediate phases.

### Verify Reanimated
`react-native-reanimated` v4.1.1 is already installed. Confirm it works with Expo 54 babel preset (no config change expected). Run `npx expo start --ios` to verify no crash.

## Phase 1: Theme System (new color architecture)

**Old system:** Single hardcoded palette in `Colors.ts` accessed via `Colors.light.primary`.
**New system:** 6 switchable palettes via React Context, persisted to AsyncStorage.

| Action | File | Details |
|--------|------|---------|
| Create | `mobile/constants/ColorPalettes.ts` | Direct port from Figma repo `src/app/design/colorPalettes.ts`. 6 palettes: Magical Dreams (default), Rainbow Adventure, Forest Friends, Ocean Waves, Candy Shop, Sunset Stories. Each has 10 color tokens: primary, primaryHover, secondary, secondaryHover, accent, accentHover, background, cardBg, textDark, textMuted. |
| Create | `mobile/contexts/ThemeContext.tsx` | Port from web version. Replace `localStorage` → `AsyncStorage`. Remove all CSS variable updates. Export: `ThemeProvider`, `useTheme()` → `{ palette, setPalette }`. Load saved palette ID on mount, default to `'magical'`. |
| Modify | `mobile/app/_layout.tsx` | Add `<ThemeProvider>` wrapper around existing providers. Remove any imports of deleted `Colors.ts`. |

**Every screen henceforth uses `const { palette } = useTheme()` and accesses colors via `palette.colors.primary` etc. No more `Colors.light.*` anywhere.**

## Phase 2: Shared Components (populate `mobile/components/`)

All new files. These are the building blocks every screen uses.

| File | Spec |
|------|------|
| `AnimatedPressable.tsx` | Wraps `Pressable` with Reanimated. `onPressIn` → `withSpring(0.96)`, `onPressOut` → `withSpring(1)`. Props: `onPress`, `style`, `children`, `disabled`. |
| `GradientBackground.tsx` | Wraps `expo-linear-gradient` `LinearGradient`. Props: `colors: [string, string]`, `children`, `style`. Defaults to vertical gradient, full screen. |
| `ProgressBar.tsx` | Track + fill bar. Fill width animated with `withTiming`. Props: `progress: number (0-1)`, `trackColor`, `fillColor`, `height` (default 8). Border radius on both track and fill. |
| `StoryCard.tsx` | Card for library grid. 3:4 aspect ratio `expo-image` cover, rounded-2xl, shadow. Below image: title (Nunito 600, 14px), child name badge, page count. Uses `AnimatedPressable` for tap. Uses `useTheme()` for colors. |
| `SectionCard.tsx` | Container card. White background, `borderRadius: 24`, shadow (`shadowColor: #000`, `shadowOpacity: 0.08`, `shadowRadius: 16`, `elevation: 4`). Props: `children`, `style`. |
| `useAnimatedEntrance.ts` (hook) | Returns `animatedStyle` with fade-in (`opacity: 0→1`) + slide-up (`translateY: 20→0`) using `withTiming({ duration: 400 })`. Param: `delay` in ms. |

## Risks & mitigations

- **Risk:** react-native-reanimated babel plugin compatibility with Expo 54
  - Mitigation: Expo 54's `babel-preset-expo` handles Reanimated automatically. Test in Phase 0.
- **Risk:** `react-native-pager-view` gives flat swipe, not 3D page curl like react-pageflip
  - Mitigation: Flat swipe matches mobile platform conventions. Acceptable trade-off.
- **Risk:** Theme persistence race condition (AsyncStorage is async, first render uses default)
  - Mitigation: Splash screen covers the brief flash of default palette on cold start.
- **Risk:** Create wizard drops fields from old form (childGender, specialFriendName, etc.)
  - Mitigation: All dropped fields are optional in the API (`services/api.ts`). Safe to omit.
