## Context

The current story reader (`mobile/app/story/[id]/read.tsx`) uses `react-native-pager-view` for flat horizontal swipes between pages. This was an explicit FC-001 trade-off: "Flat swipe matches mobile platform conventions. Acceptable trade-off."

That trade-off doesn't hold for this product. The Figma mock specified a drag-and-hold page curl matching Apple Books, and that affordance is core to the bedtime-reading experience the app is selling: a parent's finger physically peels the page back, the child sees the next illustration appear under it, hold pauses mid-curl, release commits or snaps back. Flat swipes feel like flipping through a slideshow, not reading a book.

This plan replaces the pager with a Skia + Reanimated implementation derived from William Candillon's [Riveo Page Curl](https://github.com/wcandillon/can-it-be-done-in-react-native/tree/master/season5/src/Riveo) — the gold-standard RN page curl, which uses `@shopify/react-native-skia` and a custom SkSL shader to do real GPU-accelerated curl with shadow.

## Goals

- Drag from the right edge to peel the current page; the next page is visible underneath as the curl progresses.
- Hold mid-drag — page stays partially curled at finger position.
- Release: if dragged past ~50% of screen width, animate to fully turned (next page); otherwise spring back.
- Same gesture mirrored for backward turn (drag from left edge).
- 60fps on iPhone 12+ class hardware in landscape orientation with 4K story illustrations.
- All existing reader features preserved: auto-hiding controls, page dots, confetti, "The End" overlay, landscape lock, portrait rotation prompt.

## Non-goals

- Multi-axis curl effects (e.g. corner peel). Single-axis (vertical spine, page peels right→left or left→right) is enough.
- Animated bookmark, back-of-page paper texture, or other ornamentation beyond the curl + shadow itself.
- Android-specific tuning. iOS-first; Android parity is a follow-up if Skia behaves differently there.
- Configurable curl speed / styles in user settings. Single tasteful default.
- Replacing controls overlay or end overlay — they layer on top of the Skia canvas unchanged.

## Proposed approach

**Library swap.** Add `@shopify/react-native-skia` (~5MB). Remove `react-native-pager-view` from the reader (kept in `package.json` for now in case of revert, removed in cleanup pass after this lands). Keep `react-native-reanimated` (4.1.1) and `react-native-gesture-handler` (2.28.0) — both already installed, both required by the curl effect.

**Architecture.** Replace the `<PagerView>` block in `read.tsx` with a Skia `<Canvas>` containing two `<Image>` layers stacked at the same coordinates: bottom = next page, top = current page (curling). A `Gesture.Pan()` from gesture-handler drives a Reanimated `SharedValue` for the curl origin (finger x position). That shared value is consumed by an `<ImageShader>` running the Riveo curl SkSL shader, which warps the top page into a curled mesh and renders shadow under the curl.

**Multi-page navigation logic** (not in Riveo demo, our addition):
- Track current page index in React state (same as today).
- On gesture release: if curl progress > 0.5, run `withTiming` from current curl position to fully-turned, then increment `currentPage` and reset curl progress.
- If progress ≤ 0.5, run `withSpring` back to 0.
- Backward turn: pan from left edge with negative direction; same shader, reversed arguments.
- First page: ignore back-pan. Last page: forward pan still works but commits to "The End" overlay.

**Image loading.** Story page imageUrls are remote (Cloud Storage). Use Skia's `useImage()` hook to async-load each page as a `SkImage`. Preload current + next + previous to avoid mid-turn pop-in. Show a placeholder color while loading.

**Tap zones, controls, dots, end overlay.** All remain as React `<View>`/`<Pressable>` siblings layered on top of the Skia `<Canvas>`. They don't interfere with Skia rendering and continue to function identically.

**Shader port.** Riveo's `pageCurl.ts` shader (~80 lines of SkSL) ports verbatim. Uniforms: `pointer` (xy of finger), `origin` (anchor edge), `container` (page size). The math is portable — no app-specific changes.

## Critical files

- `mobile/app/story/[id]/read.tsx` — replace PagerView with Skia Canvas + curl logic. ~150–250 net new lines.
- `mobile/components/PageCurl/Curl.tsx` (new) — Skia Canvas wrapper, image stack, shader application.
- `mobile/components/PageCurl/pageCurl.ts` (new) — port of Riveo's SkSL shader and uniform helpers.
- `mobile/components/PageCurl/usePageImages.ts` (new) — hook that loads current/next/prev page images via Skia `useImage` and manages preload window.
- `mobile/package.json` — adds `@shopify/react-native-skia`.
- `mobile/app.json` — Skia may need a plugin entry depending on the Expo SDK version.

## Reuse

- `react-native-reanimated` (already installed) — drives shared values for curl progress, spring animations on release.
- `react-native-gesture-handler` (already installed) — Pan gesture for the drag.
- `expo-screen-orientation` (already installed) — landscape lock stays as-is.
- `useQuery(['story', id], () => getStory(id))` — same data fetch.
- `react-native-confetti-cannon` — same end-of-book confetti, layered on top.
- The existing top bar, page dots, page counter, "The End" overlay, portrait rotation prompt, and error/loading states all stay React-rendered, layered above the Skia canvas. No structural changes to those components.

## Risks & mitigations

- **Risk:** SkSL shaders are harder to debug than JS. A bug in the curl math produces visually broken output with no stack trace.
  - **Mitigation:** Port Riveo's shader byte-for-byte first, get it rendering against a static test image before integrating. Don't modify the math until the basic effect works.

- **Risk:** Skia adds ~5MB to bundle size. iOS app size matters for App Store conversion.
  - **Mitigation:** Acceptable — page curl is core UX and Skia unlocks future polish (custom shaders, gradients, etc.) for other screens too. Document the size cost in CLAUDE.md.

- **Risk:** Loading remote story images into Skia takes longer than React Native's `<Image>`. Mid-turn the next-page Skia image may not be ready, causing a blank page or pop-in.
  - **Mitigation:** Preload current + next + previous via `useImage` on page change. Show palette-colored placeholder under the curl if next-page image not yet loaded — better than blank.

- **Risk:** New Architecture / Reanimated 4 / gesture-handler 2.28 / Skia compatibility. One of these may not be perfectly aligned and break the build.
  - **Mitigation:** First commit installs Skia and verifies a trivial Canvas renders before building the curl. Bail early if there's a fundamental incompatibility — fall back to the perspective-tilt simpler path documented in the spike notes.

- **Risk:** Drag gesture conflicts with the existing tap zones (left/center/right) for prev/next/toggle controls.
  - **Mitigation:** Tap zones become tap-only (no drag detection); pan gesture is on the Skia canvas itself underneath. Pan only activates after a small movement threshold (e.g. 8px) so taps don't accidentally start a drag.

- **Risk:** Backward turn UX is ambiguous — does the user pan from left, or pan right-to-left from anywhere?
  - **Mitigation:** Match Apple Books: pan starting from the left ~25% of the screen → backward; pan starting from the right ~25% → forward. Center taps toggle controls (existing behavior).

- **Risk:** Two-finger or fast multi-swipe gestures interleaving mid-animation cause state inconsistency.
  - **Mitigation:** Pan gesture is single-touch (`Gesture.Pan().maxPointers(1)`). New gestures during a turn animation are queued or ignored.

## Rollout

- Single feature branch: `feature/fc-011-page-curl`.
- One PR per FC rule: dedicated PR.
- Manual testing on iOS simulator + physical device. Test on iPhone 12+ class hardware specifically — older devices may struggle with Skia + 4K image rendering.
- No staging environment; reader changes don't touch backend.
- **Rollback:** revert PR. Reader returns to PagerView.
