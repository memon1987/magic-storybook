## Context

Today every page of every story bakes the narration text into the illustration and pins it to a bottom band — see `backend/src/prompts/illustration.ts:62-107`, the `TEXT TO EMBED IN THE IMAGE` block plus the `BOTTOM quarter` rule. That choice was rational when the only text-rendering option we had was the image generator, but it has three concrete costs:

1. **Spelling errors.** Gemini 3.1 Flash Image is documented at ~90% in-image text accuracy. On a 6-page story that's a coin-flip per book that *some* word is wrong. Children learning to read notice.
2. **Static layout.** Text always at the bottom regardless of the scene composition (focal character on the right, focal character at the bottom, etc.). The result reads like a textbook caption rather than a picture book.
3. **Typography is out of our control.** FC-014 just shipped three writing styles (Bouncy Rhymes / Gentle Refrains / Sweet & Simple) but we can't make the *visual* feel of the text match the *voice* of the prose — Gemini picks a generic hand-lettered look every time.

The parent overhaul plan (`~/.claude/plans/lets-pick-back-up-warm-map.md`) calls FC-015 the largest mobile lift in the batch and is the last of four FCs. The parent plan's design — and what this file executes — is to render text **inside the Skia canvas, in the same Group as the page image, so the existing page-curl shader treats the composite as one surface and curls them together**.

Why that architecture matters: an earlier draft put text in a React Native `<Text>` overlay positioned on top of the Skia canvas. That looked OK statically but broke during the curl gesture (image deformed via shader, RN text stayed flat) and required a fade-out hack that killed the "pre-read while peeling" affordance. Putting the text inside Skia, in the same `<Group layer={...}>` that the curl shader operates on, means the curl shader composites image + text into the offscreen layer first, then deforms that composite. No mismatch, no fade hack, no coordinate-system translation.

## Goals

- Stop embedding narration text in the page illustration. Reserve negative space at the model-chosen `textPosition` so the Skia text layer has somewhere clean to land.
- Render narration text inside the Skia canvas via `SkParagraph`, using fonts that match the page's writing style (Baloo 2 → Bouncy, Nunito → Gentle, Quicksand → Sweet & Simple).
- Text becomes part of the curling surface — the existing page-curl shader is unchanged.
- Backwards-compatible: existing stories (no `textPosition` field on their pages) continue to render with their baked-in text and no Skia overlay.
- Optional `soundEffects[]` array per page: short stylized onomatopoeia words Gemini renders into the illustration (single words are the case Gemini handles reliably).

## Non-goals

- Per-word animation on the text layer. Static composition only in v1.
- Speech bubbles, dialogue tails, or comic-style typography. Those are a different interaction pattern.
- Replacing fonts on legacy stories. Pre-FC-015 stories keep their baked-in text exactly as generated.
- A user-facing "change font" or "change layout" picker. The writing-style picker (FC-014) implicitly drives the font, the model picks the position. No additional surface.
- Per-word emphasis animation, accent gradient, or typographic flourishes beyond size+color for `emphasizedWords`.

## Proposed approach

### Backend — story prompt extension (`backend/src/prompts/story.ts`)

Each per-page object in the JSON schema gains three optional fields:

```jsonc
{
  "pageNumber": 1,
  "text": "...",
  "sceneDescription": "...",
  // NEW for FC-015:
  "textPosition": "top" | "bottom" | "left" | "right" | "center-overlay",
  "soundEffects": ["Whoosh!"],          // optional, 0-2 short single words
  "emphasizedWords": ["BIG", "tiny"]    // optional, words from `text` to render larger / accent-colored
}
```

Prompt instructions:

- Pick `textPosition` based on the scene composition. If the focal character is bottom-right, prefer `top` or `left`. If the scene is wide and balanced, `bottom` is fine. `center-overlay` is reserved for moments of intensity (a single short emphatic line) since it sits on top of the illustration.
- `soundEffects` is for moments where stylized text in the *image itself* fits naturally (a "BOOM!" near an explosion, "Splash!" near a jumping frog). Single words only; max two per page. Keep them genuinely useful — not sprinkled on every page.
- `emphasizedWords` must be a subset of `text` (verbatim). The Skia layer renders these slightly larger and in the page's accent color.

### Backend — illustration prompt rewrite (`backend/src/prompts/illustration.ts`)

The `TEXT TO EMBED IN THE IMAGE` block is removed for any call where `pageText` is not passed. New rule when `textPosition` is provided: **do NOT bake narration into the image**, and **reserve negative space** at the indicated position (a slightly lighter or softly washed area where text will be overlaid by the app). When `soundEffects` is present, add a short instruction to render those *single words* in stylized in-image typography near the relevant action.

Backwards compatibility: if `pageText` IS passed (the legacy code path used by older callers / regenerations of pre-FC-015 stories), the old text-embedding block runs as today. New stories generated through the FC-015 path call `buildIllustrationPrompt` *without* `pageText` and *with* the new `textPosition` + `soundEffects` args.

### Backend — types (`backend/src/types/index.ts`)

Extend `StoryPage` and `PageDocument` with the three new optional fields. Extend `StoryPageWithImage` accordingly. No changes to `GeneratedStory` shape — pages already nest inside it.

### Backend — service (`backend/src/services/gemini.ts`)

`generateAllIllustrations` now passes the new per-page fields through to `buildIllustrationPrompt` and stops sending `pageText`. The page generation loop is otherwise unchanged (still uses character refs + page-1 setting ref). `soundEffects` is appended to the prompt only when non-empty.

### Backend — route (`backend/src/routes/stories.ts`)

The Firestore page-write batch persists `textPosition`, `soundEffects`, and `emphasizedWords` alongside the existing fields. The response payload includes them in the `pages[]` array. Validation: `textPosition` is constrained to the five enum values if present; `soundEffects` and `emphasizedWords` are arrays of strings (cap each at length ≤ 4 to bound payload).

### Mobile — type extension (`mobile/services/api.ts`)

`StoryPage` gains the same three optional fields. Constants define the enum and the writing-style → font-family mapping in one place so the reader can stay declarative.

### Mobile — Skia font registration (`mobile/hooks/useStoryFonts.ts`, NEW)

A small hook that loads the three Google Fonts already used elsewhere (Baloo 2 Bold, Nunito 700, Quicksand 600) into Skia via `useFonts` from `@shopify/react-native-skia`:

```ts
const fonts = useSkiaFonts({
  'Baloo 2': [require('@expo-google-fonts/baloo-2/Baloo2_700Bold.ttf')],
  'Nunito':  [require('@expo-google-fonts/nunito/Nunito_700Bold.ttf')],
  'Quicksand': [require('@expo-google-fonts/quicksand/Quicksand_600SemiBold.ttf')],
});
```

Returns the Skia `FontMgr` (or `null` while loading). Reader gates Skia text rendering on this being non-null.

### Mobile — PageTextLayer (`mobile/components/PageCurl/PageTextLayer.tsx`, NEW)

A Skia node fragment (returns Skia draw children, NOT a RN `<View>`):

```tsx
<Group>
  <SkParagraph
    paragraph={paragraph}
    x={layoutX}
    y={layoutY}
    width={textBlockWidth}
  />
</Group>
```

Where `paragraph` is built once via `Skia.ParagraphBuilder.Make(...)` with:
- Font family selected by writing style
- Base size that scales with screen width (≈ height/16 for landscape phone)
- Text alignment and word-wrap appropriate for the reservation zone
- `emphasizedWords` rendered with `pushStyle({ fontSize: base * 1.25, color: palette.accent, fontStyle: { weight: 700 } })` then popped per emphasized word

Layout zones (in pixel-density-multiplied coords matching the curl Group's transform):
- `top`: x = inset, y = inset, width = canvas - 2*inset; vertical alignment top
- `bottom`: x = inset, y = h - textBlockH - inset, width = canvas - 2*inset
- `left`: x = inset, y = (h - textBlockH)/2, width = ~40% of canvas
- `right`: x = canvas - textBlockW - inset, y = (h - textBlockH)/2, width = ~40% of canvas
- `center-overlay`: centered horizontally, vertically biased to upper-third; rendered with a translucent backing rect for readability over the illustration

A subtle translucent rounded rect (low-alpha white or warm cream) sits behind the paragraph to keep contrast against busy illustrations. Color taken from `palette.colors.cardBg` with alpha ≈ 0.85.

If `textPosition` is undefined (legacy story), the component renders nothing — text is already baked in the image.

### Mobile — Curl integration (`mobile/components/PageCurl/Curl.tsx`)

Two structural changes:

1. The current page Group gains `<PageTextLayer page={currentPage} ... />` as a sibling of `<SkiaImage image={currentImage} />` *inside* the inner `<Group layer={Paint with RuntimeShader}>`. Text is now part of what the curl shader composites and deforms.

2. The next page (rendered as the static underlay) also gains `<PageTextLayer page={nextPage} ... />` as a sibling of `<SkiaImage image={nextImage} />`. So when the user peels the current page back, the underlying next page's text is also visible — preserving the pre-read affordance.

`Curl` accepts a new prop: `currentPageData: StoryPage | null` and `nextPageData: StoryPage | null`. The reader passes these through.

### Mobile — Reader pass-through (`mobile/app/story/[id]/read.tsx`)

Pass `pages[currentPage]` and `pages[currentPage + 1]` into `<Curl />` as the new props. Pass `story.writingStyle` so the right font is picked. The synthesized cover page (FC-012) has no `textPosition` — it renders no Skia text layer (cover already has text baked in by `titlePage.text`).

### Sequencing

Backend first (types → prompts → service → route → tsc → commit). Then mobile (api type → font hook → PageTextLayer → Curl → read.tsx → tsc → commit). Single PR (`feature/fc-015-skia-text-composition`) so the backend + mobile changes ship together — the backend change is a no-op for old clients (they keep ignoring the new optional fields) and the mobile change is a no-op for old stories (no `textPosition` → no overlay).

## Reuse

- `@expo-google-fonts/{baloo-2,nunito,quicksand}` — already in `package.json`; the TTFs they ship are reused for Skia registration (no new font files in the bundle)
- `@shopify/react-native-skia` 2.2.12 — already loaded; uses its built-in `useFonts` + `Skia.ParagraphBuilder` (no new dep)
- `useTheme()` palette — accent color + cardBg for emphasis + backing rect already exposed
- The `Group layer={<Paint>...}` page-curl shader pattern in `Curl.tsx` is unchanged — composition naturally extends to text

## Risks & mitigations

- **Risk:** Gemini reflexively picks `top`/`bottom` for `textPosition` and never uses `left`/`right`/`center-overlay`, defeating the "playful placement" goal.
  - **Mitigation:** Story prompt explicitly instructs the model to choose based on focal-character location, with examples. If post-ship inspection shows uniform `bottom` across pages, iterate the story prompt — not the reader code — and re-evaluate.
- **Risk:** `SkParagraph` word-wrap looks bad on long single-line narration in the narrow `left`/`right` zones (~40% of canvas).
  - **Mitigation:** Story prompt is told to keep text short for `left`/`right` positions specifically. Reader caps text-zone width at min(40% canvas, 380pt). If a paragraph still doesn't fit, fall back to `bottom` at render time.
- **Risk:** Skia font registration fails silently (typo in font filename, asset bundler doesn't pick it up).
  - **Mitigation:** `useStoryFonts` returns `null` until fonts are ready; reader logs the failure and falls back to rendering nothing (image-only). User sees image but no narration overlay — visible bug, not a silent crash. The legacy text-in-image path still works for old stories.
- **Risk:** Translucent backing rect washes out the illustration in `center-overlay` mode.
  - **Mitigation:** Tunable alpha; start at 0.85 and adjust based on visual review of the first 5 generated stories. If still ugly, drop to drop-shadow on the text instead of a backing rect.
- **Risk:** The two-page text rendering (current page text inside curl Group + next page text in underlay) is twice the Skia work per frame; older devices may stutter during curl.
  - **Mitigation:** Both `<PageTextLayer>`s are static (no per-frame uniforms — only the curl shader's uniforms animate). Skia caches static draws inside layers. Should be near-free; verify on the test device after first build.
- **Risk:** Gemini still bakes narration text into the image despite the new "do NOT include narration" instruction in the illustration prompt, leading to *double-rendered* text (in-image + Skia overlay).
  - **Mitigation:** The new prompt path explicitly omits `pageText` from the prompt entirely (not just toggling an instruction). The model has no story text to embed because we don't send it any. Belt-and-braces.

## Rollout

- Single PR / single branch. No feature flag.
- Verify locally on dev client first (Expo Go does NOT support Skia advanced features per `~/.claude/projects/.../memory/reference_skia_dev_client.md`).
- After merge, generate ≥3 stories spanning all 3 writing styles and visually inspect:
  - text position varies across pages within a story
  - fonts visibly differ across writing styles
  - page-curl gesture: text deforms with the page; pre-read affordance works (peel reveals next page's text)
  - legacy stories still render their baked-in text correctly
- Rollback: revert the merge commit. Backend change is a strict superset (old clients unaffected); mobile change reads new fields if present, ignores otherwise. Stories generated mid-rollout have the new fields persisted but won't render the overlay after revert — they fall back to the (empty) text-in-image path. Worst-case visible artifact: 1-2 stories generated during the FC-015 window have NO visible text after a rollback, until they're regenerated. Acceptable.

## Open questions

- Should `center-overlay` be removed? It's the riskiest position (sits on top of the illustration). Tentatively keeping it for emphasis moments; happy to drop if the reviewer flags real readability concerns.
- For `emphasizedWords`, do we want the model to also choose an emphasis *style* (size vs color vs both)? v1 says no — reader picks one consistent treatment per writing style — keeps the design surface small. Revisit if it feels monotonous after 5+ stories.
