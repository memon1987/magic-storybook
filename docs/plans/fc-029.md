## Context

In the story reader, tapping is overloaded: it both toggles the info bars (title/close + page dots/counter) and navigates via hard-coded zones — left 25% = previous, right 25% = next, center 50% = toggle. So a tap meant to reveal the bars frequently lands in an edge zone and **accidentally flips the page** (reported on build 11 / FC-026, which otherwise renders well).

**Decisions locked with the user:**
1. **Decouple tap from navigation** — a tap *anywhere* only toggles the controls bars; tap never navigates.
2. **Add a backward page-curl swipe** — the curl was forward-only; add a left-to-right drag that curls the **previous** page back on and commits to `currentPage - 1`.

Forward navigation (swipe-left curl) is unchanged; the dots remain a jump-to-any-page affordance.

## Key findings (validated)

- **The existing GLSL shader (`pageCurl.ts`) is reusable for backward — no rewrite.** Feeding the curl-layer top = previous image with `origin` held at `width` and `pointer` animated `0 → width` makes the fold `x = width - (origin - pointer)` sweep **left → right**, so the previous page fills in **from the left edge**. No mirror variant.
- **`usePageImages` already returns `{ prev, current, next }`** with `prev` gated (page 0 → null; FC-022 empty-URL synthetic end page → null). No hook change — read.tsx just forwards `pageImages.prev`.

## Approach

### Curl.tsx (primary)
- **Tap decouple:** `Gesture.Tap().maxDistance(8).onEnd(() => runOnJS(onTap)())`; `onTap` prop becomes `() => void`; remove the `TapZone` type.
- **Direction state machine:** `direction` React state (`'forward'|'backward'`) + worklet-readable `isBackward` shared value. Decided once at pan `onStart` from `sign(e.translationX)` (activeOffsetX gates at ±10px so the sign is the drag direction).
  - Forward: `origin = e.x`, `pointer = max(0, min(origin, e.x))`; onEnd commit if `(origin-pointer)/width > 0.25 && currentPage < totalPages-1` → `withTiming(pointer→0)` then `onPageChange(currentPage+1)`; else spring to `origin`.
  - Backward: `origin = width`, `pointer = clamp(translationX, 0, width)`; onEnd commit if `pointer/width > 0.25 && currentPage > 0` → `withTiming(pointer→width)` then `onPageChange(currentPage-1)`; else `withSpring(pointer→0)` and on finish collapse to identity (`origin = pointer`) + `setDirection('forward')`.
- **Render swap:** `curlImage = backward ? previousImage : currentImage` (in the shader layer); `revealImage = backward ? currentImage : nextImage` (sharp contain beneath, opacity-gated). `revealOpacity = isBackward ? 1 : (pointer < origin ? 1 : 0)` — forward gates next (FC-026 anti-bleed), backward keeps current visible beneath the incoming previous page. Ambient backdrop stays keyed to `currentImage` in both modes.
- **Reset:** `useLayoutEffect` on `[currentPage, width]` resets `origin = pointer = width`, `isBackward = false`, `direction = 'forward'` — the canonical rest after any commit/resize.

### read.tsx
- Drop `type TapZone` import; `handleTap = () => setControlsVisible(v => !v)`; pass `previousImage={pageImages.prev}` to `<Curl>`. `handlePageChange` (absolute `setCurrentPage`) already handles backward (`currentPage-1`, can be 0). Controls auto-hide timer unaffected.

## Critical files
- `mobile/components/PageCurl/Curl.tsx` — tap decouple, direction state machine, backward gesture + render swap
- `mobile/app/story/[id]/read.tsx` — toggle-only `handleTap`, pass `previousImage`, drop `TapZone`
- `mobile/components/PageCurl/usePageImages.ts` — **no change** (already exposes `prev`)
- `mobile/components/PageCurl/pageCurl.ts` — **no change** (shader reused both directions)

## Edge cases
- Page 0: `prev = null`, `canBackward = false` → right-drag rubber-bands (curl layer null, current shown).
- Last content page + synthetic "The End" (FC-022) and cover (FC-012 index 0): forward guard still lets you reach but not pass the end; backward reveals the prior loaded page; backward from cover blocked by page-0 guard.
- Direction is set at `onStart` and the curl/reveal image swap is React state (one render per swipe); a 1-frame image-source swap at gesture start/reset is accepted (documented for on-device QA).
