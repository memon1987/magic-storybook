## Context

The login screen has a "Continue with Google" button that's a stub (`Alert.alert('Coming soon')` at `mobile/app/(auth)/login.tsx:110`); register has no social option at all. Social sign-in lowers signup friction for the parent-facing app. We're on the **Firebase Web JS SDK v11**, whose easy web methods (`signInWithPopup`/`signInWithRedirect`) **do not work in React Native** — so for any provider the pattern is: acquire a provider token natively → exchange via Firebase `signInWithCredential(...)`. Sessions persist for free thanks to the just-merged `getReactNativePersistence` fix (PR #32).

Because offering Google on iOS triggers **App Store Guideline 4.8** (a privacy-equivalent login — Sign in with Apple — must also be offered), this FC ships **both Google and Apple** together so the next iOS production submission is compliant in one PR.

## Goals

- Working "Continue with Google" on **login + register**, both platforms, via the native account sheet.
- Working "Sign in with Apple" on **login + register**, **iOS only**, satisfying Guideline 4.8.
- All social sessions persist across cold-start (already handled by existing persistence init).
- Backend token verification unchanged — both flows yield standard Firebase users for project `ai-storybook-app-2025`.

## Non-goals

- No `users` Firestore profile collection (none exists today; auth-only is preserved).
- No web/Android Apple sign-in (Apple is iOS-native only here; Android users use Google).
- No migration to `@react-native-firebase` (staying on the Web JS SDK).
- No changes to email/password flows.

## Proposed approach

**Token acquisition:**
- **Google** — `@react-native-google-signin/google-signin` (native sheet; ships an Expo config plugin) → `GoogleAuthProvider.credential(idToken)` → `signInWithCredential`.
- **Apple** — `expo-apple-authentication` (iOS native) with a SHA-256-hashed nonce → `OAuthProvider('apple.com').credential({ idToken, rawNonce })` → `signInWithCredential`. `expo-crypto` generates + hashes the nonce.

**Dependencies** (install via `npx expo install` to pin to SDK 54):
- `@react-native-google-signin/google-signin`
- `expo-apple-authentication`
- `expo-crypto`
- `expo-dev-client` — **add explicitly**; it's missing from `package.json` despite `developmentClient: true` in eas.json (latent fragility; fix in this PR).

**`mobile/app.json`** — extend `plugins`:
```json
"plugins": [
  "expo-router",
  "expo-font",
  "expo-screen-orientation",
  ["@react-native-google-signin/google-signin", { "iosUrlScheme": "com.googleusercontent.apps.<REVERSED_IOS_CLIENT_ID>" }],
  "expo-apple-authentication"
],
"ios": { "bundleIdentifier": "com.aistorybook.app", "buildNumber": "11", "usesAppleSignIn": true }
```
`iosUrlScheme` = the **reversed iOS** OAuth client ID, hardcoded (not secret; ships in Info.plist anyway). Config-plugin params can't read `EXPO_PUBLIC_*` from static `app.json`.

**OAuth client IDs — the footgun:** `GoogleSignin.configure({ webClientId })` MUST be the **Web** client ID (the audience Firebase validates), NOT the iOS client. Wrong value → `idToken` comes back null and the credential build fails. Mapping:
| ID | Used as | Where |
|---|---|---|
| Web client ID | `webClientId` in configure() + Firebase token audience | `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` |
| iOS client ID | `iosClientId` in configure(); reversed form → `iosUrlScheme` | `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` + app.json |
| Android client ID | resolved natively via package + SHA-1 | console only, no runtime var |

**Env vars** (mirror existing `EXPO_PUBLIC_FIREBASE_*` plumbing in all 4 places: `mobile/.env`, `mobile/.env.example`, and the `env` block of all three `mobile/eas.json` profiles):
- `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`
- `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`

(Apple needs no client-ID env var for the native iOS flow.)

## Code sketches

`signInWithGoogle()` (handles v13+ `{ type, data: { idToken } }` and older flat shape):
```ts
await GoogleSignin.hasPlayServices({ showPlayServicesUpdateDialog: true });
const res: any = await GoogleSignin.signIn();
if (res?.type === 'cancelled') throw new Error('Google sign-in was cancelled.');
const idToken = res?.data?.idToken ?? res?.idToken;
if (!idToken) throw new Error('No Google ID token — check EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID is the WEB client.');
return (await signInWithCredential(auth, GoogleAuthProvider.credential(idToken))).user;
```

`signInWithApple()` (nonce: hash for Apple, raw for Firebase):
```ts
const rawNonce = (await Crypto.getRandomBytesAsync(16)).reduce((s,b)=>s+b.toString(16).padStart(2,'0'),'');
const hashedNonce = await Crypto.digestStringAsync(Crypto.CryptoDigestAlgorithm.SHA256, rawNonce);
const cred = await AppleAuthentication.signInAsync({
  requestedScopes: [AppleAuthentication.AppleAuthenticationScope.FULL_NAME, AppleAuthentication.AppleAuthenticationScope.EMAIL],
  nonce: hashedNonce,
});
if (!cred.identityToken) throw new Error('No Apple identity token.');
const credential = new OAuthProvider('apple.com').credential({ idToken: cred.identityToken, rawNonce });
return (await signInWithCredential(auth, credential)).user;
```
Swallow the user-cancel cases in the screen handlers (Apple throws `ERR_REQUEST_CANCELED`; Google uses the `cancelled` branch) without an error alert.

## Console / setup steps (order matters)

1. **Firebase Console → Auth → Sign-in method → enable Google** (set support email). Auto-creates the **Web client** → copy to `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`.
2. **GCP (`ai-storybook-app-2025`) → OAuth consent screen** — configure + add test users (or publish).
3. **GCP → Credentials → OAuth client → iOS** (bundle `com.aistorybook.app`). Forward form → `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`; reversed → `app.json` `iosUrlScheme`.
4. **GCP → Credentials → OAuth client → Android** (package `com.aistorybook.app` + **SHA-1** from `eas credentials -p android`). Missing SHA-1 → `DEVELOPER_ERROR` (code 10).
5. **Apple Developer → App ID `com.aistorybook.app` → enable "Sign in with Apple"** capability (EAS manages the entitlement via `usesAppleSignIn: true`). Requires the paid Apple Developer account.
6. **Firebase Console → Auth → enable Apple provider.** For the iOS-native flow, enabling is sufficient (Services ID / key config is only for web/Android OAuth redirect, which we're not doing).

## Risks & mitigations

- **iOS-client-vs-web-client footgun** → null idToken. *Mitigation:* explicit error message + plan table; verify `webClientId` is the Web client.
- **Android `DEVELOPER_ERROR`** → wrong/missing SHA-1. *Mitigation:* pull SHA-1 from `eas credentials`, not a local keystore.
- **Apple nonce mismatch** → Firebase rejects. *Mitigation:* hash (SHA-256) the nonce for Apple, pass the **raw** nonce to Firebase — the sketch encodes this.
- **No OTA + native modules** → must ship a **new EAS dev-client build**; old clients lack the native modules. `@react-native-google-signin` and `expo-crypto` touch their native module at *import time* (TurboModule getEnforcing / requireNativeModule), which would crash the app at **launch** on a stale client — and `firebase.ts` is imported app-wide. *Mitigation:* these native modules are **lazily imported** (`await import(...)`) inside `signInWithGoogle`/`signInWithApple`, so email/password keeps working on a stale client and any crash is confined to the user who taps a social button. Still rebuild before testing; call out in release notes.
- **Apple is iOS-only** → button must be gated on `Platform.OS === 'ios'` + `isAvailableAsync()`; Android users use Google. *Mitigation:* conditional render.
- **`expo-dev-client` added** changes the lockfile → rebuild after install.
