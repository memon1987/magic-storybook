## Context

`mobile/` has **zero** test infrastructure — no `test` script, no runner, no test files (verified 2026-06-22 during FC-022, re-verified 2026-07-05: `mobile/package.json` has only `start/android/ios/web/lint` scripts). Pure logic that is easy to get wrong ships verified only by manual walkthrough: `readerPageLabel` ([`mobile/components/PageCurl/paging.ts`](../../mobile/components/PageCurl/paging.ts) — cover/end-page offset math, written *explicitly* to be unit-testable, FC-022) and `computeGrid` ([`mobile/hooks/useResponsive.ts`](../../mobile/hooks/useResponsive.ts) — pure column-count solver, exported "for unit testing (FC-024)" per its own comment, FC-026). Meanwhile the repo has **no GitHub Actions workflows at all** (no `.github/` directory) — the only automated gate is `cloudbuild.yaml`, which runs backend `npm ci && npm test` *at deploy time*, after merge. Nothing gates PRs. Multiple recent plans (FC-040 contract item 4, FC-031, FC-035) contain "if a mobile test runner exists (FC-024)…" escape hatches; this plan removes the excuse.

Backend already uses Vitest (`backend/package.json` → `"test": "vitest run"`, vitest `^4.1.7`, no config file — default globs find `src/**/__tests__/*.test.ts`, 7 test files exist).

**Runner decision (pre-made): jest-expo, not vitest.** Vitest would be consistent with the backend, but the mobile module graph is not plain TS: even "pure" helpers live in files that import `react-native` and `react-native-safe-area-context` at module top (`useResponsive.ts` does exactly this). jest-expo is the official Expo preset — it ships the transform, `transformIgnorePatterns`, and RN/Expo module mocks that make such imports resolve out of the box; vitest would need hand-rolled aliases/mocks that break on every SDK upgrade. Backend stays on Vitest; the two runners never meet (separate packages, separate CI jobs). Decision closed — do not re-litigate.

## Goals

- `cd mobile && npm test` runs jest with the jest-expo preset and passes, with behavior tests for `readerPageLabel` (all four `hasCover`/`hasEndPage` combinations) and `computeGrid` (phone/tablet widths, min/max clamping, pathological input).
- A GitHub Actions workflow gates every PR to `main` (and pushes to `main`) on: mobile `tsc --noEmit` + `jest`, backend `tsc --noEmit` + `vitest run`.
- `mobile/package-lock.json` regenerated under **npm 10** so EAS builds keep working (FC-029 lockfile incident: lock written by npm 11 → `npm ci` failure on the EAS builder's npm 10).

## Non-goals

- **No component tests, no `@testing-library/react-native` in v1.** Keeps the dependency surface minimal (no react-test-renderer / RN testing peer-dep matrix). Natural v2 once the runner is proven: component tests for the reader and library screens.
- No `api.ts` interceptor test. Assessed 2026-07-05: the request interceptor is an inline async closure whose only logic is "if `getIdToken()` returns a token, set the Authorization header," and both `api.ts` and its `./firebase` import **throw at module load** when `EXPO_PUBLIC_*` env vars are absent (deliberate FC-guard). There is no pure helper to extract without refactoring production code, which this plan forbids. Skipped; candidate for v2 alongside a `buildAuthHeader`-style extraction.
- No changes to `cloudbuild.yaml` — it keeps owning backend deploy (and its own pre-deploy test gate). The Actions workflow *complements* it as a pre-merge gate; it does not deploy anything.
- No coverage thresholds, no e2e (Detox/Maestro), no backend test additions.

## Proposed approach

### 1. Install the runner — `mobile/`

Expo SDK is `expo ^54.0.33` → the matching preset major is **jest-expo ~54**. Install with `npx expo install` so Expo pins the exact compatible versions (expected: `jest-expo@~54.0.x`, `jest@~29.7.0`; `@types/jest@^29.x`):

```bash
cd mobile && npx expo install jest-expo jest @types/jest -- --save-dev
```

devDependencies added: `jest`, `jest-expo`, `@types/jest` — nothing else. Then in `mobile/package.json`:

- scripts: add `"test": "jest"`
- top-level jest config (no separate `jest.config.js` needed for this little):

```json
"jest": { "preset": "jest-expo" }
```

Default jest `testMatch` picks up `**/__tests__/**/*.test.ts` — same convention the backend already uses. `mobile/tsconfig.json` has no `types` array, so `@types/jest` is auto-included and `tsc --noEmit` type-checks the test files with no tsconfig change.

### 2. Lockfile — npm 10 semantics (MANDATORY)

Local dev machines run npm 11; the EAS builder runs npm 10. After the installs above, regenerate the lock under npm 10 and prove it in the command output:

```bash
cd mobile && rm -rf node_modules package-lock.json \
  && npx -y npm@10 --version \
  && npx -y npm@10 install \
  && npx -y npm@10 ci
```

The `--version` line must print `10.x`; the trailing `npm ci` proves the lock is self-consistent under npm 10.

### 3. Tests — behavior, realistic inputs, each fails if the contract breaks

**`mobile/components/PageCurl/__tests__/paging.test.ts`** — `readerPageLabel`, all four synthetic-page combinations:

- cover + end (production shape since FC-022): `pageCount: 7` (cover + 5 story + end) → index 0 = `"Cover"`, index 6 = `"The End"`, index 1 = `"1 / 5"`, index 5 = `"5 / 5"` (off-by-one at both seams).
- cover only: `pageCount: 6, hasEndPage: false` → index 0 = `"Cover"`, index 3 = `"3 / 5"`.
- end only: `pageCount: 6, hasCover: false` → index 5 = `"The End"`, index 0 = `"1 / 5"`.
- neither: `pageCount: 5` → index 0 = `"1 / 5"`, index 4 = `"5 / 5"`.

**`mobile/hooks/__tests__/computeGrid.test.ts`** — `computeGrid` (imported from `../useResponsive`; the module's RN imports are why jest-expo exists):

- Phone width, defaults: `available = 350` (iPhone 390 minus 2×20 gutter) → raw solver gives 1, **min-clamps to 2 columns**; `cellWidth = (350 − 14) / 2 = 168`, `gap = 14`.
- Tablet width, defaults: `available = 960` (iPad 1024 minus 2×32) → 5 columns (`floor((960+14)/(178+14)) = 5`).
- Max clamp: `available = 1302` (12.9" iPad landscape 1366 minus gutters) → raw 6 → clamped to 5.
- Pathological input (Slide Over / Stage Manager, insets > width): `available = -50` → 2 columns, `cellWidth = 0`, no `NaN`/negative (the documented guard).
- Options override: `computeGrid(600, { target: 100, gap: 10, min: 1, max: 10 })` → 5 columns, `cellWidth = (600 − 40) / 5 = 112`.

That is ≥10 meaningful assertions before any padding; each pins an externally observable contract (labels users read; column counts the library renders), not implementation internals.

### 4. CI — new `.github/workflows/ci.yml`

Two independent jobs, triggered on `pull_request` targeting `main` **and** `push` to `main`. Node 20 in both — matches the EAS builder and the `node:20` steps in `cloudbuild.yaml`. No deploy steps anywhere.

```yaml
name: CI
on:
  pull_request: { branches: [main] }
  push: { branches: [main] }
jobs:
  mobile:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: mobile } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: npm, cache-dependency-path: mobile/package-lock.json }
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npm test
  backend:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: backend } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: npm, cache-dependency-path: backend/package-lock.json }
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npx vitest run
```

(Executor may format long `with:` blocks multi-line; keep the steps and triggers exactly as above.)

## Risks & mitigations

- **jest-expo major ≠ Expo SDK major** silently produces broken transforms (the classic jest-expo trap). Mitigation: install via `npx expo install` (pins compatibility) and assert `jest-expo` resolves to `54.x` in the lockfile; do not hand-pick versions from memory.
- **npm-11 lockfile bricks EAS builds** (FC-029 incident). Mitigation: §2's mandatory npm-10 regeneration with `--version` proof in the DoD.
- **`expo lint` flags jest globals** (`describe`/`it` undefined) if `eslint-config-expo@~10` lacks a jest env for test files. Mitigation: if (and only if) lint fails, add a `**/__tests__/**` override enabling `env: { jest: true }` to the ESLint config — smallest possible tweak; do not disable rules globally.
- **CI job drift vs. cloudbuild** (two places running backend tests). Accepted: intentional redundancy — Actions gates merge, Cloud Build gates deploy; both run the same `vitest run`.
- **Lockfile merge conflict with a concurrent mobile-dep FC** (FC-039 if it adds `expo-haptics`). Mitigation: Wave A, merge FC-024 first (see contract); the later PR rebases and re-runs §2.

## Rollout

No runtime behavior changes — production code untouched; mobile app binary unaffected (devDependencies are not bundled), backend deploy pipeline unaffected. Ships as one PR; the CI gate takes effect for every subsequent PR the moment this merges. Rollback = revert the PR (deletes workflow + tests + devDeps). No EAS build required.
