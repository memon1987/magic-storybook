## Context

The page-curl reader works but feels clunky in beta (build 13):

1. **Turning a page is slow.** A turn requires a tracked drag ≥25% of the screen width (`COMMIT_THRESHOLD_RATIO` in [`mobile/components/PageCurl/Curl.tsx`](../../mobile/components/PageCurl/Curl.tsx)) followed by a 300ms commit animation. The user does the animation's work with their finger; a bedtime reader wants a one-tap turn.
2. **The screen randomly flashes on animation transition.** See root-cause analysis below — the prime suspect is a commit-ordering race between the UI-thread shared values and the JS-thread page-state swap.
3. **The grey title/footer bars behave inconsistently with page turns.** Two compounding causes: (a) `handlePageChange` in [`mobile/app/story/[id]/read.tsx`](../../mobile/app/story/[id]/read.tsx) calls `setControlsVisible(true)` on **every** page turn, so the bars flash up uninvited after each turn and auto-hide 4s later; (b) tap currently only toggles bars (FC-035 removed tap-to-navigate because the old 25/50/25 zones caused accidental flips), so tap semantics and turn semantics feel unrelated.
4. **The ✕ exit button is nearly unreachable.** The top bar uses `paddingHorizontal: 12` with **no safe-area insets**. In landscape on notched/Dynamic-Island iPhones the left inset is ~59pt, so the ✕ sits inside the sensor housing / rounded-corner region — visually clipped and hard to hit.

Direction (user, 2026-07-05): bring back **tap-to-advance**, but as a **fire-and-forget animated curl** — the curl is no longer tracked to a finger; a tap triggers a self-running page-turn animation. Deconflict tap-to-turn from tap-to-toggle-bars. Reposition the ✕.

### Flash root-cause analysis (from code read, to be confirmed on device)

On forward commit today: `withTiming(pointer → 0)` finishes on the UI thread → `runOnJS(onPageChange)(currentPage + 1)` → React re-renders with the new page → `useLayoutEffect` resets `pointer/origin = width`. But `curlImage`/`revealImage` swap in the React commit while the *shared values* reset propagates to the UI thread separately. If a frame renders with the **new** images but the **old** `pointer = 0`, the new current page is drawn fully peeled and `revealOpacity = 1` shows the *next-next* page full-screen for a frame — a wrong-page flash. The backward path has a second documented artifact: `onStart` renders one flat frame before `runOnJS(setDirection)` lands. Both are inherent to splitting one logical transaction (swap page + reset curl) across two threads. The fix below makes the commit ordering explicit rather than racy.

## Goals

- One tap turns the page with a smooth, self-running curl animation (forward and backward).
- Zero wrong-page flashes across repeated turns (acceptance: 20 consecutive forward + backward turns on device with no visible flash).
- Bars appear only when asked for: tap-to-toggle in a dedicated zone; **no** auto-show on page turn.
- ✕ button fully inside the safe area with a comfortable hit target.

## Non-goals

- Re-adding a finger-tracked drag curl (can return later as a secondary gesture in its own FC if missed).
- Changing the curl shader (`pageCurl.ts`), `usePageImages`, or `paging.ts`.
- Portrait-mode redesign, sound effects, haptics beyond a possible light tap-feedback.

## Proposed approach

### 1. Tap zones (deconfliction) — `Curl.tsx`

Replace the `Pan` gesture entirely. A single `Gesture.Tap()` reads `e.x` and routes:

- `x < width * 0.20` → `turnBackward()`
- `x > width * 0.80` → `turnForward()`
- middle 60% → `onTap()` (toggle bars — unchanged contract with `read.tsx`)

This is the Apple Books / Kindle convention, but with a *larger* toggle center (60% vs the old 50%) than the pre-FC-035 layout that caused misfires — and a misfired turn is now visible (a full animated curl) and trivially reversible with one tap on the opposite edge, instead of an instant confusing jump. If beta still shows misfires, fallback option (noted, not planned): move bar-toggling to top/bottom horizontal bands and let the full middle band navigate.

Taps during an in-flight animation are **ignored** (an `isAnimating` shared value guards entry) — no queueing, no mid-flight reversal. Edge-zone taps on cover/last page no-op exactly like today's `canForward`/`canBackward`.

### 2. Programmatic curl animation — `Curl.tsx`

New `turnForward()` / `turnBackward()`:

- **Forward:** set `direction='forward'` (React state) + `origin = width`, `pointer = width`, then `withTiming(pointer → 0, ~500ms, Easing.inOut(cubic))`; on completion, commit (below). The peel originates at the right edge — same visual as a full swipe, without the drag.
- **Backward:** set `direction='backward'`, `isBackward = true`, `pointer = 0` **before starting** (the previous page starts fully curled at the left), then `withTiming(pointer → width)`. Because the tap→turn decision happens on the JS thread *before* any animation starts, the direction-state/image swap lands in a React commit **before** the first animated frame — structurally eliminating FC-035's one-frame-flat artifact at backward start.
- Timing constant `TURN_MS ≈ 500` (tune 450–600 on device). One shared constant for both directions.

### 3. Flash-free commit — `Curl.tsx`

Make the end-of-animation transaction explicit with a **settle gate**:

- On completion the composite is exactly "revealed page full-screen" (forward: `revealOpacity=1` showing `nextImage`). Set a `settling` flag that **freezes** the reveal layer at opacity 1 and keeps the curl layer hidden, *then* `runOnJS(commit)` → `onPageChange(±1)`.
- The new render's `useLayoutEffect` (existing) resets `pointer/origin = width`, clears `settling`, and only then does the flat "current page" layer take over — and its image is the **same `SkImage` object** the reveal layer was already showing (`usePageImages` shifts the same decoded images), so the handoff is pixel-identical. No frame can show a fully-peeled new page or the next-next page.
- The ambient backdrop still swaps to the new page's blur at commit; if the hard swap reads as a "background flash" on device, crossfade it (~150ms opacity ramp) — decide during on-device verification.

### 4. Bars behave — `read.tsx`

- `handlePageChange` no longer calls `setControlsVisible(true)` — turning a page never summons the bars; if they're visible, a page turn resets the 4s auto-hide timer rather than re-showing.
- `handleTap` (center-zone) stays the only toggle. Dots row / page counter unchanged.

### 5. Reachable ✕ — `read.tsx`

- Top bar consumes `useSafeAreaInsets()` (provider already at root since FC-026): `paddingTop: max(12, insets.top)`, `paddingLeft: max(12, insets.left) `, `paddingRight: max(12, insets.right)`.
- Move the ✕ from top-**left** to top-**right** (modal-close convention, and the right inset side is symmetric); mirror the empty spacer to keep the title centered. Bump the pressable to 44×44 with `hitSlop={16}`.

## Critical files

- `mobile/components/PageCurl/Curl.tsx` — remove Pan; tap-zone router; `turnForward`/`turnBackward`; `isAnimating` guard; settle-gate commit; drop the mid-gesture `setDirection` machinery notes that no longer apply.
- `mobile/app/story/[id]/read.tsx` — stop auto-showing bars on page change; safe-area top bar; ✕ to top-right with larger target.

## Reuse

- `pageCurl.ts` shader, `usePageImages`, `readerPageLabel` — untouched.
- Existing `withTiming`/easing + `revealOpacity` gating pattern — extended, not replaced.
- `useSafeAreaInsets` — already provided at the root (FC-026).

## Risks & mitigations

- **Zone misfires return (the FC-035 complaint).** Mitigated by narrower edges (20% vs 25%), a visible/reversible animated turn instead of an instant flip, and bars no longer auto-appearing (fewer taps needed overall). Fallback documented in §1 if beta disagrees.
- **Settle gate gets the state machine wrong** (stuck `settling`, ignored taps forever). Keep the gate minimal: it is cleared unconditionally in the existing `useLayoutEffect` reset that already runs on every `currentPage`/`width` change.
- **Removing swipe surprises existing beta users.** The dots row still jumps anywhere; release notes for the next build call out "tap the page edges to turn."
- **Backward math regression** (reveal gate, end-of-curl rest state). The FC-035 review found bleed bugs here twice — verification explicitly re-runs those checks.
