# Plan: Migrate production to baked-in text + OCR text-repair; delete Skia overlay

## Context

FC-019 ran a backend spike comparing text-rendering paradigms and reached a decision (see
`docs/investigations/fc-019-text-paradigm-comparison-2026-05-16.md`):

> **Production should generate illustrations with the narration text BAKED INTO the image**
> (Gemini 3.1 Flash), anchored by the FC-013 character machinery (per-character model-sheets +
> cast lineup + pin-first-K canonical anchors), with **OCR-based detect-and-regenerate** to catch
> Flash's ~10% stochastic text jumbles. Gemini 3 Pro was rejected (unfixable character drift).

The current production pipeline does the opposite: it reserves blank negative space in the image
and renders narration as a **Skia overlay** on top in the mobile reader (FC-015/FC-018). User
feedback drove FC-019: the overlay never feels "like a true kids' book written and illustrated by
an author." The spike proved baked text + OCR-repair delivers integrated, legible, author-style
text while preserving character consistency.

This plan **promotes the proven spike mechanics into the production path** and **fully deletes the
FC-015/FC-018 Skia overlay machinery**.

**Sequencing (user decision, Option C):** ship this synchronously now; the async/job-model refactor
(FC-017) lands as a *separate* follow-on FC. This plan includes the guardrails that make the sync
model viable in the interim and explicitly hands the durable timeout fix to FC-017.

## Goals

- Production stories generate with narration text **baked into the illustration** (no overlay).
- Character consistency preserved via the FC-013 machinery promoted from the spike: per-character
  model-sheets + a cast-lineup reference + **pin-first-K canonical anchors**.
- Every page is **OCR-verified** (recall ≥ 0.6 AND precision ≥ 0.75) and regenerated on failure,
  bounded for the sync timeout budget.
- The FC-015/FC-018 **Skia overlay code is fully deleted** (per user: no flag, no fallback).
- A backend **test framework** is stood up; the detection metric + anchor logic are unit-tested
  (this is a production behavior change → tests required by the workflow).
- Spike scaffolding (route, env flags, unused Recraft secret, `spike-*` GCS objects) is torn down.

## Non-goals

- **Async job model / request resumption (FC-017).** This plan keeps the synchronous request and
  only adds bounded guardrails. The durable 600 s fix is FC-017's job.
- **Migrating or back-filling existing stories.** Pre-FC-020 stories will render without their
  overlay text (see Risks). Acceptable because the app is internal-testing-only (not launched).
- **Re-opening the model decision.** Flash + baked text is decided; Pro/Recraft are out.
- **New writing styles, art styles, or story-text changes.**

## Proposed approach

### Backend — promote the baked path to production (`backend/src/services/gemini.ts`)

1. **Make the baked generator the production generator.** Today `generateAllIllustrations` calls
   `generateIllustration` (text NOT baked, `textPosition` passed). Rewire it to use the baked +
   OCR-verified generator (the spike's `generateIllustrationBaked`, generalized: drop the
   `spikeSubdir` param so it uploads to the normal `stories/{id}/page-N` prefix; keep
   `verifyText` but default it **on** in production). Delete the old `generateIllustration`.

2. **New production generation order** (consistency-preserving *and* timeout-aware):
   1. Character model-sheets — **parallel** (`generateCharacterReference`, unchanged).
   2. Cast lineup — generated once when the story has **>1 character** (`generateCastReference`);
      persisted and used as a fixed canonical reference on every page.
   3. Title page — sequential (`generateTitlePage`, now baked text via the same path).
   4. **First K pages (K=2) — sequential**, to establish the canonical anchors (matches the
      winning spike config `anchorPages=2`).
   5. **Remaining pages — parallel**, each referencing: char model-sheets + cast lineup + the K
      canonical anchors. Because later pages anchor only on the *fixed* first-K pages (not on each
      other), they have no inter-dependency and parallelize safely — this is the key timeout lever.
   - Reference-set construction (char sheets + cast + first-K canonical anchors) is lifted from
     `runGeminiBakedVariant` in `spike.ts` into a production helper.

3. **OCR text-repair always on in production**, but bound the cost: production attempt cap of
   **2** total generations per page (`MAX_TEXT_GEN_ATTEMPTS` stays 3 for the spike; production
   passes its own cap). A page that still fails after the cap keeps its best-F1 candidate (never
   blocks a story). OCR fails open (already implemented).

4. **Persist `castReferenceUrl`** on the story document (alongside `characterReferenceUrls`).

5. **Broaden the retry predicate.** `isRetryableError` currently retries only **503**. A FC-020
   test run hit a transient **500 INTERNAL** from Gemini on one page and it broke immediately
   (no retry) → placeholder page. Broaden retries to cover **500/502/503/504** (and network
   resets) under the existing exponential backoff, so transient 5xx don't drop a page. This is the
   single most impactful reliability fix observed during validation.

### Backend — prompts & types

6. `backend/src/prompts/illustration.ts` — delete the `textPosition` branch and
   `TEXT_POSITION_RESERVATION`; the **baked `pageText` path becomes the only path**.
   `soundEffects` + `emphasizedWords` continue to be baked (they're illustration guidance now,
   not overlay metadata).
7. `backend/src/prompts/story.ts` — stop instructing Gemini to emit `textPosition`; stop
   validating it. Keep `soundEffects` + `emphasizedWords` generation.
8. `backend/src/types/index.ts` — delete `TextPosition` type + `TEXT_POSITIONS`. Add
   `castReferenceUrl?` to `StoryDocument`.
9. `backend/src/routes/stories.ts` — stop persisting `textPosition`; persist `castReferenceUrl`.
   Keep persisting `soundEffects` / `emphasizedWords`.

### Mobile — delete the overlay (per the FC-020 surface map)

10. **Delete** `mobile/components/PageCurl/PageTextLayer.tsx` and `mobile/hooks/useStoryFonts.ts`.
11. `mobile/components/PageCurl/Curl.tsx` — remove both `PageTextLayer` render calls and the
    overlay-only props (`fontMgr`, `writingStyle`, `textColor`, `accentColor`, `haloColor`). Keep
    all gesture/curl logic.
12. `mobile/app/story/[id]/read.tsx` — remove the `useStoryFonts` import/call and the
    `fontMgr`/`haloColor` props passed to `Curl`.
13. `mobile/services/api.ts` — delete `TextPosition`, `WRITING_STYLE_FONT_MAP`,
    `DEFAULT_OVERLAY_FONT`, and `StoryPage.textPosition`. Keep `soundEffects` / `emphasizedWords`
    on `StoryPage` (still returned by the API; just unused by the reader now).
14. `mobile/constants/ColorPalettes.ts` — delete `haloColor` from the interface and all 6 palettes.

### Testing (new — `backend/`)

15. Stand up **Vitest** in `backend/` (dev-dep + `test` script + minimal config). Add unit tests:
    - `scoreBakedText` token logic via an **injected/mocked** Vision client: clean text → high
      recall+precision; a hallucinated-extra-text fixture → precision below threshold; missing-text
      fixture → recall below threshold. (Refactor `scoreBakedText` to accept an injectable client,
      or extract the pure recall/precision math into a tested helper fed OCR strings.)
    - `bakedTextPasses` / `bakedTextF1` boundary cases.
    - The pin-first-K canonical-anchor selection (pure helper extracted from the loop): given N
      rendered pages and K, the right K fixed anchors are chosen and later pages don't reference
      each other.
    - The verify-regenerate decision (pure): a failing-then-passing score sequence keeps the
      passing candidate; an all-failing sequence keeps the highest-F1 one within the cap.

### Spike teardown (final phase of this PR)

16. Delete `backend/src/routes/spike.ts` and its mount in `backend/src/index.ts`. Remove the
    `SPIKE_*` env vars from `.env.example`. (`backend/scripts/{validate-ocr-detector,
    diagnose-text-metrics}.js` stay — reusable diagnostics.)
17. Remove the unused `RECRAFT_API_KEY` Secret Manager binding from the Cloud Run service.
18. Delete spike artifacts from GCS: `stories/*/spike-pro/`, `stories/*/spike-recraft/`,
    `stories/*/spike-flash/`, and the extra `character-refs/cast-*` from spike runs.

## Risks & mitigations

- **Existing stories lose their text.** Pre-FC-020 images have reserved blank space; text lived
  only in the overlay. Deleting the overlay leaves a visible gap. *Mitigation:* app is
  internal-testing-only — document that pre-FC-020 stories should be regenerated/deleted; do not
  back-fill. (Surfaced to and accepted by the user.)
- **600 s timeout on long (12-page) stories.** Baked text + OCR-repair + char refs on a sync
  request. *Mitigations:* (a) only first-K pages are sequential, the rest parallel; (b) OCR-repair
  regens are per-page independent, so a regen doubles only that page's task, not the batch;
  (c) production attempt cap = 2; (d) cap concurrency on the parallel batch to avoid OOM/connection
  exhaustion. *Residual risk explicitly handed to FC-017 (async job model).*
- **OCR false positives blocking good pages.** Validated low (clean floor precision 0.94 vs 0.75
  threshold across 12 renders). *Mitigation:* keep best-F1 candidate within the cap; fail open on
  OCR error; thresholds are constants, tunable without a redeploy of logic.
- **Cast/anchor refs push payloads near Gemini's 14-image multimodal cap.** char sheets + cast +
  K anchors must stay under the cap. *Mitigation:* K=2; cap total refs defensively (as the spike's
  `MAX_PRIOR_PAGE_REFS` did).
- **Vision OCR cost/quota in production.** Every page (+regens) OCR'd. *Mitigation:* ~$1.50/1000
  images, negligible at current volume; confirm quota; fail-open already covers outages.
- **Large atomic PR (backend bake + mobile delete must ship together)** — otherwise double-text or
  blank-gap states. *Mitigation:* single PR is correct here (one rollback unit); rely on the
  adversarial review + confirmation pass.

## Rollout

- Branch `feature/fc-020-baked-text-production`; **single PR** (atomic backend+mobile migration).
- Deploy backend from source to `ai-storybook-app-2025` (`gcloud builds submit --config
  cloudbuild.yaml --project ai-storybook-app-2025 --substitutions=COMMIT_SHA=$(git rev-parse HEAD)`).
- Mobile verified in the dev client / simulator (Skia native module → dev client, not Expo Go).
- **Peer review:** one adversarial reviewer (senior persona matched to image-pipeline/RN), then a
  scoped confirmation pass after fixes (per workflow). Not the two-reviewer tier (no money/data
  corruption), but core product output → rigorous single review + confirmation required.
- Monitor after deploy: Cloud Run request duration (timeout headroom), `[TEXT-VERIFY]` log lines
  (recall/precision distribution, regen rate), OCR-failed warnings, story-gen error rate.
- **Rollback:** revert the PR (single unit). Because old stories are already incompatible, rollback
  restores the overlay code but newly-generated post-revert stories revert to overlay behavior.

## Open questions

- **Production attempt cap = 2 vs 3?** 2 bounds the timeout better; 3 catches more jumbles. Lean 2,
  revisit if regen-still-failed rate is high. (Decide during implementation from the spike data.)
- **K (canonical anchor count) = 2 fixed, or scale with length?** Spike used 2 and it held. Lean
  fixed 2; revisit only if long stories drift late.
- **Parallel-batch concurrency cap value?** Pick from Cloud Run instance memory headroom during the
  12-page integration test.
