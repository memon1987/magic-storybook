## Context

Library-grid story covers are visibly cut off. [`mobile/components/StoryCard.tsx`](../../mobile/components/StoryCard.tsx) renders the cover with `contentFit="cover"` (line 41) inside a `coverWrap` box pinned to `aspectRatio: 3/4` (line 114, `styles.coverWrap`). Gemini-generated cover images are not 3:4, so `cover` crops the edges — slicing off the **baked-in title text** and characters. This is the exact clipping class FC-026 fixed in the reader (`fit="cover"` → `fit="contain"` + a blurred, darkened ambient backdrop behind the letterbox — see `BACKDROP_BLUR = 22` / `BACKDROP_DARKEN = 'rgba(0,0,0,0.35)'` in `mobile/components/PageCurl/Curl.tsx`). Since FC-020, title text is baked into the illustration and cannot be re-overlaid — cropping it is data loss, not just polish.

Decision (user, 2026-07-05): mirror the FC-026 fix at card scale. Do **not** change the 3:4 box — the FC-026 grid math (`computeGrid`/`cellWidth` in [`mobile/app/(tabs)/index.tsx`](../../mobile/app/(tabs)/index.tsx)) sizes cells assuming that fixed card shape.

StoryCard already uses `expo-image`'s `Image` (v`~3.0.11`), which supports a native `blurRadius` prop (points; not applied to placeholders) — no new dependency and no Skia needed at card scale.

## Goals

- Every library thumbnail shows the **full** cover image — title text and characters uncropped — in the existing 3:4 box.
- Letterbox bands read as a blurred extension of the artwork (per-card ambient backdrop), not flat/black bars.
- Zero grid-layout change: same `coverWrap` aspect ratio, same `computeGrid` cell sizing, same card chrome.
- No measurable scroll-perf regression (blur is a static native image effect, not animated).

## Non-goals

- Changing the `coverWrap` `aspectRatio: 3/4` or any `computeGrid` math from FC-026.
- Touching the reader (already fixed by FC-026) or the backend image aspect ratio (that's FC-028).
- Redesigning the placeholder / generating / failed states — chips and placeholder icon stay as-is.
- Adding dependencies (no `expo-blur`, no Skia in the card).

## Proposed approach

Single file: `mobile/components/StoryCard.tsx`. Inside the existing `coverWrap` `View`, replace the single `coverUrl` `Image` with a three-layer stack (same image URI twice — expo-image's memory/disk cache keys on the URI, so the source downloads and decodes once):

1. **Backdrop:** `<Image source={{ uri: coverUrl }} style={StyleSheet.absoluteFill} contentFit="cover" blurRadius={16} />` — fills the 3:4 box edge-to-edge; `blurRadius={16}` (points) is the card-scale analog of the reader's 22px Skia blur (cards are much smaller, so less blur reads equivalently).
2. **Dim overlay:** `<View style={[StyleSheet.absoluteFill, styles.coverDim]} />` with `coverDim: { backgroundColor: 'rgba(0,0,0,0.25)' }` — mutes the backdrop so the sharp foreground pops (reader uses 0.35; cards sit on a light UI so 0.25).
3. **Foreground:** the existing `<Image source={{ uri: coverUrl }} style={styles.cover} contentFit="contain" />` — only the `contentFit` value changes from `"cover"` to `"contain"`; `styles.cover` (`width/height: '100%'`) is unchanged.

JSX ordering keeps the existing `statusOverlay` blocks (Generating…/Tap to retry chips) **after** the image stack, so they still render on top. The `!coverUrl` placeholder branch is untouched (`blurRadius` doesn't apply to placeholders anyway). No props, exports, or call sites change — `index.tsx` is not edited.

## Critical files

- `mobile/components/StoryCard.tsx` — the only file: two-layer image stack + dim overlay inside `coverWrap`; one new style entry (`coverDim`); foreground switches to `contentFit="contain"`.

## Reuse

- `expo-image` `Image` — already imported in `StoryCard.tsx`; `blurRadius` is a built-in prop of the installed version (`~3.0.11`).
- `StyleSheet.absoluteFill` (react-native, already imported via `StyleSheet`) for both backdrop layers.
- FC-026's visual recipe (cover-fit blurred bed + darken + contain foreground) as the design contract — values re-derived for card scale, mechanism identical.

## Risks & mitigations

- **Risk:** scroll-perf regression from a second image layer + blur per card on a FlatList grid.
  - Mitigation: blur is a static, native expo-image effect computed per drawn image (not per frame, not animated); both layers hit the same cache entry. Manual checklist includes a fast-scroll perf pass on a device with a full library.
- **Risk:** blurred backdrop makes the Generating…/failed chips or placeholder harder to read.
  - Mitigation: the 0.25 dim layer increases (not decreases) chip contrast vs today's bright cover; chips render above the stack; placeholder branch is untouched.
- **Risk:** near-3:4 source images make the backdrop invisible (bands ~0px), wasting a layer.
  - Mitigation: acceptable — cost is negligible and behavior degrades to today's look without cropping. FC-028 (backend aspect-ratio pin) would shrink bands further; explicitly out of scope here.
- **Risk:** merge collision with FC-039 (edit mode also touches `StoryCard.tsx`).
  - Mitigation: sequenced in the conflict matrix — FC-038 runs in Wave A; FC-039 rebases on merged main (see `AUTONOMOUS_EXECUTION.md` §6).

## Rollout

Mobile-only, UI-only; no backend, no data, no schema. Also **repairs the look of all existing stories** (fix is render-time, like FC-026). Ships to users in the next EAS build (no OTA). Normal branch + PR, two-review gate per the Execution contract, single squash-merge.
