# Release Notes — 2026-06-22

## Summary

Fixed two distinct story-reader bugs reported from real use and shipped both to TestFlight as **iOS build #10**: (1) the reader was trapped behind an undismissable "rotate your device" overlay when the landscape lock silently no-ops, and (2) the "The End" card covered the last story page, making it unreadable. Also resolved an FC-numbering collision (renumbered the orientation fix FC-021 → FC-023) and filed FC-024 to stand up the (currently nonexistent) mobile test runner.

> **Scope note:** this session was the **mobile reader-fix thread**. The FC-017 reliability track (Phase 1 commit `a7644a6`; Phase 2 / FC-025 / PR #26 remediation) advanced in parallel and is **not** covered here.

## Changes

### New Features
- **Dedicated "The End" page** in the story reader. Reaching the end is now a real page you turn to (with confetti), mirroring the existing synthesized cover page — instead of an overlay slapped on the last story page.

### Bug Fixes
- **FC-023 (originally filed FC-021) — Reader landscape overlay never dismissed (PR #25, `9df56e7`).** The reader gated rendering on `isPortrait` (the `expo-screen-orientation` enum OR `height > width`) and relied on `lockAsync(LANDSCAPE)` actually rotating the UI. When the lock silently no-ops — iPad multitasking, iOS device-level portrait rotation-lock, simulators — the window never flips, `useWindowDimensions` stays portrait, **and** the orientation listener never fires a landscape event (interface orientation never changed). So the gate could never clear and rotating the phone did nothing; the user was trapped with only a Close button. **Fix:** always render the reader (the page-curl is dimension-driven), derive `isPortrait` purely from `useWindowDimensions`, drop the unreliable orientation state + listener, and replace the blocking overlay with a small non-blocking auto-dismissing "Best read in landscape" hint. Lock is now best-effort and logs on failure instead of swallowing it.
- **FC-022 — "The End" card covered the last story page (PR #27, `c5d5456`).** The card rendered as a full-screen dark scrim the instant `isLastPage` was true. **Fix:** append a synthetic image-less "The End" page; the card + confetti now trigger on `isEndPage` only, so the last *story* page renders with no overlay and is fully readable. The Curl paints the image-less page solid black; forward-commit from the last story page already works once `totalPages` grows.

## Key Decisions & Rationale

- **Always-render the reader vs. fix the portrait detection (FC-023).** Rejected patching detection. The disease was *gating render on an orientation signal the failure path makes unsatisfiable*. Removing the gate cures it at the root. `useWindowDimensions` (`height > width`) is the only reliable orientation signal because it reflects what's *actually rendered*; the `ScreenOrientation` enum reflects *interface* orientation, which doesn't change when the lock no-ops.
- **Rejected `UIRequiresFullScreen: true` (FC-023).** It would make the landscape lock reliable on iPad but disables Split View / Slide Over **app-wide** and needs a native rebuild — too high a cost for one screen. iPads rotate freely, so they can't get stuck regardless.
- **Dedicated end page vs. over-scroll trigger (FC-022).** The page-curl only emits a *forward-commit* event, and only when `currentPage < totalPages - 1`. On the last page a forward swipe springs back and emits nothing. An over-scroll trigger would require inventing a new gesture event and is undiscoverable (the page just springs back). A real appended page reuses all existing machinery (curl, dots, counter, null-image rendering).
- **Didn't stand up a mobile test runner in-scope.** `mobile/` has zero test infra; standing up vitest/jest-expo is a separate medium change. Chose to extract the error-prone logic into a pure helper now and file **FC-024** for the runner, rather than balloon a small bug-fix PR.
- **FC-021 numbering collision → renumber the orientation fix to FC-023.** "FC-021: GCP-side latency levers" already existed (created 2026-05-26, published in `RELEASE_2026-05-27.md`). The orientation fix mistakenly reused FC-021. The GCP entry has seniority and is cemented in published release notes, so it keeps FC-021; the orientation fix renumbered to FC-023. PR #25 / git commits still say "FC-021" (immutable history; noted in the FC entry and plan).

## Discoveries

- **`expo-screen-orientation` `lockAsync` silently no-ops** on iPad (multitasking-capable apps), when the iOS device-level portrait rotation-lock is on, and on simulators. When it no-ops, `addOrientationChangeListener` also never fires (the *interface* orientation didn't change, only the physical device). Net: never trust the lock or the enum for "can the user read this" — use rendered dimensions.
- **No OTA configured** in this project — verified there is no `expo-updates`, no EAS Update channel, and no GitHub Actions workflow. Code merges do not deploy.
- **EAS `autoIncrement` + `appVersionSource: local`** writes the bumped `buildNumber` back into local `app.json` at build time; if left uncommitted it creates ambiguity about the next build's base (the 9-vs-10 risk we hit).
- **`read.tsx` is the app's only orientation consumer** (verified) — no global lock, so `unlockAsync` on unmount is safe for the screens you return to.
