## Discoveries

- **Nano Banana 2 image latency vastly exceeds spec in practice today.** Single observed 8-page run had per-image generation times of **28s, 46s, 53s, 79s, 88s** for pages 4, 1, 8, 3, 6 respectively (pages 2, 5, 7 had not completed by the time we sampled). The published spec is **4-6s/image**. That's 5-15× the spec for the slow pages. Confirmed the deployed model on `main` and on the running Cloud Run revision is `gemini-3.1-flash-image-preview` — this is real model latency, not a misconfiguration.

- **Cold start hit this run.** The Cloud Run container started at 13:15:04, the same second the request arrived. First-request setup overhead is folded into the timing for this run. Subsequent requests on the same warm instance should be faster.

- **Text generation also took a 503 retry.** At 13:15:07 the text gen hit a 503 ("model experiencing high demand") and retried 2s later, succeeding. Suggests Gemini-side demand pressure today, which usually correlates with elevated latency on non-503 calls too.

- **The 8-page "long" length is a meaningful UX cost.** Story `b1a1a5be...` was 8 pages, 2× the 4-page benchmarks we've been quoting. With per-page latency this slow, an 8-page story takes 5+ minutes versus the ~30-50s we promised to the user for short stories. The wizard's length step should probably set expectations differently for "long" — or we cap the parallelism/pages until latency is back in spec range.

- **The hardcoded "Gemini 3 Pro Image" log line** has been wrong since the FC-002 model swap on 2026-04-24. We caught it today only because we were grepping logs for model identification. Code reviews don't catch hardcoded model names in console.log strings — worth refactoring to log `${IMAGE_MODEL}` directly so the line stays correct on future model swaps.
