### Bug Fixes

- **Story generation 503 → 500 cascade** (`3f01121`): `generateStory()` had no retry wrapper around `ai.models.generateContent`, so a single transient 503 from gemini-3-flash-preview ("model experiencing high demand") immediately bubbled as 500 to the client. The retry loop existed only on `generateIllustration`. Fix: same exponential-backoff loop (3 attempts, 2s → 4s → 8s, gated on `isRetryableError`) added to `generateStory`.
- **Library list 500** (Firestore composite index): `where(userId).where(status).orderBy(createdAt)` required a composite index that didn't exist. Created via `gcloud firestore indexes composite create` — built and READY mid-session.
- **Story generation 504 timeout**: backend was completing in 130–307s, but Cloud Run had a hardcoded 120s request timeout AND mobile axios had a 120s timeout. Bumped both to 600s.
- **Wizard "almost completes and then restarts"**: `GeneratingOverlay` had a fake progress bar that looped 5%→85%→5% every 24s. Replaced with monotonic asymptotic curve toward 95% so the bar smoothly approaches and never resets.
- **FC-001 review nits** (PR [#2](https://github.com/memon1987/ai-storybook-app/pull/2), `e3c73f1`):
  - `ThemeContext` value object wrapped in `useMemo` — was creating new ref every render, causing all `useTheme()` consumers to re-render.
  - `CustomTabBar` active-tab pill hidden when the elevated Create tab is focused — was visually colliding with the elevated circle.
  - Replaced `const Container: any = ...` in `settings.tsx` with two render branches (Pressable vs View).
  - Removed `setStepIndex(0)` / `setFormData(INITIAL_FORM)` inside `mutation.onSuccess` — fired after `router.replace` unmounted the component.
- **Corrupt placeholder app icons**: `icon.png`, `splash-icon.png`, `adaptive-icon.png`, `favicon.png` were 553-byte 48×48 placeholders with bad PNG CRC chunks. Crashed Expo's jimp-based prebuild ("Crc error -172777548 - 1008826906"). Regenerated as valid solid-yellow PNGs (1024 icon, 512 splash, 48 favicon).
- **Reader render error** ("GestureDetector must be used as a descendant"): added `<GestureHandlerRootView style={{ flex: 1 }}>` wrapper to `app/_layout.tsx`. FC-011's `Curl.tsx` uses `GestureDetector`; the root wasn't wrapped.

## Key Decisions & Rationale

- **FC-001 Phase 0 deletes deferred to Phases 7/8.** The plan's Phase 0 originally deleted `Colors.ts`, `Typography.ts`, `preview.tsx` upfront, but 8 screens still imported `Colors` and `_layout.tsx` still routed to `preview`. Deleting at Phase 0 would have left the app unbootable across all intermediate phases. Each file moved to the phase that removes its last importer. Plan file updated to reflect this.

- **Image model: Nano Banana 2 over Nano Banana Pro.** User asked for faster, gave full discretion. Researched current options (April 2026): `gemini-3.1-flash-image-preview` ships ~90% text accuracy in 4–6s vs Pro's ~94% in 24–35s. The text-in-illustration UX (Dr. Seuss style embedded text) is the product differentiator, so the 4-point accuracy drop is real. User accepted the trade explicitly. If quality regressions show up on real stories, revert is one constant in `gemini.ts:28`.

- **Backward curl deferred in FC-011.** Riveo's shader is right-edge-anchored. Doing left-anchored backward curl requires either a mirrored shader or non-trivial coordinate gymnastics. Shipping forward-only ships ~80% of the bedtime-story UX in v1; backward stays as instant tap (matching today's PagerView behavior). Documented in plan + commit + PR.

- **Skia path over alternatives.** When user requested page curl, evaluated three approaches: (1) drop-in library, (2) custom Reanimated + Skia (chosen), (3) `react-pageflip` in WebView. Existing RN page-curl libraries are mostly unmaintained and likely to feel janky on New Architecture. WebView kills the native feel. Skia + custom shader is the only path that gets Apple Books-quality output.

- **Bundled FC-011 build-unblockers in PR #3.** Asset regen + GestureHandlerRootView + CNG gitignore are technically infra fixes unrelated to the page curl, but they were needed to test the page curl end-to-end. Bundling them keeps PR #3 self-contained ("merge this PR, the page curl works"). Tagged `[no-plan: ...]` in commit messages.

- **One-PR-per-FC kept clean despite scope.** FC-001 → PR #1. Post-review fixes for FC-001 → separate PR #2. FC-011 → PR #3. No bundling of unrelated FCs into a single PR. Future rollbacks stay clean.

- **Plan-first surfaced FC-011 mid-session.** User asked for the page-curl feature mid-session; rather than just coding, surfaced that this was L-sized, did 30 min of research (WebSearch + WebFetch on Riveo), wrote `docs/plans/fc-011.md`, got approval, then implemented. The plan-first delay paid off — the implementation went smoothly because the architecture (gesture composition, useLayoutEffect for page-swap atomicity, multi-page wrapper around Riveo's single-page demo) was thought through before code.

## Discoveries

- **Skia ships a native module → cannot run in Expo Go.** Added a reference memory ([Skia needs dev client](../../../.claude/projects/-Users-zmemon-ai-storybook-app/memory/reference_skia_dev_client.md)) so this gotcha doesn't surprise the next native-module decision (mmkv, vision-camera, purchases, etc.). Same constraint will apply.
- **Cloud Run was on 120s timeout, not the documented 300s default.** The service was created with `--timeout=120` at some earlier point. Discovered while diagnosing the 504s.
- **Firestore composite indexes need explicit creation** for compound `where + where + orderBy` queries. The library list query had been silently 500-ing for any user that successfully completed a story. The error log includes a click-through URL Google generates that auto-creates the index — used `gcloud firestore indexes composite create` instead for reproducibility.
- **`expo-doctor` and `tsc --noEmit` pass cleanly across all 13 of today's commits.** Static checks aren't a substitute for runtime QA, but they did catch a `react-native-reanimated` `SharedValue` import path mismatch in `SplashScreenAnimated.tsx` and a couple of TypeScript inference issues during FC-011.
- **Riveo's shader uses physical pixels (PixelRatio-scaled), not logical pixels.** The outer Group `transform={[{ scale: 1/pd }]}` and inner Group `transform={[{ scale: pd }]}` undo each other for the rendered output, but the shader sees coordinates in pd-scaled space. Replicated the trick verbatim in `Curl.tsx`.
- **`/ultrareview` doesn't exist as a real Claude Code skill** despite being referenced in the runtime's system prompt. Fell back to `/review` (single-agent) for PR #1.
