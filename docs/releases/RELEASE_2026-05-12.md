## Changes

### New Features
- **FC-015 Skia narration overlay** (PR #9, squash-merged as `262c230`). Replaces text-baked-into-illustration with text composed inside the Skia canvas, in the same `<Group layer={Paint with RuntimeShader}>` that the page-curl shader operates on. Per-page LLM-chosen `textPosition` (`top`/`bottom`/`left`/`right`/`center-overlay`); writing-style picks the font (Bouncy → Baloo 2, Gentle → Nunito, Sweet & Simple → Quicksand). Optional `soundEffects[]` (short stylized words still rendered IN image — Gemini handles single words reliably) and `emphasizedWords[]` (highlighted in overlay). Curl shader is unchanged — it composites image+text into the offscreen layer first, then deforms the composite, so text deforms WITH the page (no fade hack, pre-read affordance preserved).

## Key Decisions & Rationale

- **FC-015 architecture: Skia text inside the curl Group, NOT React Native overlay.** v1 of the parent plan put text in an RN `<Text>` overlay outside the Skia canvas. That broke during the curl gesture (image deformed via shader, text stayed flat) and required a fade-out hack that killed the pre-read affordance. The Skia-internal approach means the curl shader composites image+text into the offscreen layer first, then deforms the composite — text curls with the page naturally, no coordinate translation, real fonts, no fade hack. User's "flatten as a single image" intuition unlocked this design.

- **Default textPosition to `'bottom'` instead of leaving undefined when Gemini drops it.** Gemini occasionally omits "MUST include" fields under load. Without the default, FC-015's no-text-in-image contract would produce a page with no narration anywhere — strictly worse than pre-FC-015. The default ensures every page always has visible narration.

- **`fit="cover"` over `fit="contain"` on the SkiaImage.** Letterbox bands meant the negative-space text positions Gemini reserved INSIDE the image didn't line up with PageTextLayer's canvas-relative positions — text would float on black bars. Cover-cropping the edges is acceptable since the story prompt already requires landscape with central focal subject.

- **Removed `maxLines: 6` silent truncation in the Skia paragraph.** Silent truncation in a children's book is the worst failure mode — visible overflow is debuggable, missing words aren't. The story prompt is sized to fit the zone; if it overflows we'll iterate the prompt, not the renderer.

- **Did NOT downgrade reanimated 4.x → 3.x as a workaround for the device crash.** User explicit constraint: keep reanimated 4 + new architecture + worklets. Investigate root cause instead. Bigger debugging burden but preserves the FC-011/015 architecture.

- **Picked "AI Storybook Magic" as the App Store listing name** because "AI Storybook" was taken (in App Store Connect's global namespace — could be our own stale draft from a prior attempt or someone else's app). Display name on the device can stay "AI Storybook" via `app.json`'s `name` field; Apple only enforces uniqueness on the listing name.

- **Committed the auto-bumped `app.json` `buildNumber`** rather than gitignoring it. EAS's `autoIncrement: true` writes the new value back to the file after every build, and committing keeps the history of what got built. Alternative was to gitignore the field entirely, which we judged less debuggable.

## Discoveries

- **Production .ipa crashes on real iPhone 16e (iOS 26.2) but Debug sim build works.** Crash signature is striking:
  - Thread 10 `com.facebook.react.runtime.JavaScript`: Hermes crashes in `String.prototype.match` dereferencing UTF-16 bytes (`/Use…` — likely the start of `/Users/expo/workingdir/...`) as a JS object pointer.
  - Thread 2 `com.meta.react.turbomodulemanager.queue`: caught NSException, was converting to JS error via `convertNSExceptionToJSError` → `_NSCallStackArray objectAtIndex:` → `backtrace_symbols` → `dyld3::MachOLoaded::findClosestSymbol` → BAD_ACCESS.
  - Sequence: a TurboModule call threw an Obj-C exception, RN tried to convert it to a JS error, the dyld symbol-resolution during stack-trace serialization failed → memory corruption → Hermes died in unrelated code on the JS thread.

- **Three crash hypotheses tested + busted** (in order):
  1. Lockfile mismatch / dep tree corruption — fixed lockfile, build #6 still crashed.
  2. Unused autolinked native modules (`expo-secure-store`, `react-native-pager-view`) throwing during TurboModule registration — removed them, build #6 still crashed.
  3. `EAS_USE_PRECOMPILED_MODULES=1` shipping precompiled .xcframeworks incompatible with iOS 26.2 dyld — set to `0`, build #7 still crashed.

- **Strongest remaining hypothesis: Debug-vs-Release config difference.** Hermes runs interpreted source in Debug but AOT-compiled bytecode in Release. Bridgeless mode is fully enforced in Release; Debug has fallback paths. Optimizer can expose latent JS undefined-behavior in Release that Debug masks. Local sim was Debug; EAS production is Release.

- **EAS Submit prints "✖ Something went wrong" even on successful submissions.** Misleading — the second submit attempt for build #4 actually succeeded despite the error message. Confirmed by the build appearing in App Store Connect and by build #7 submitting cleanly with the same flow + a clear "✔ Submitted!" message.

- **CocoaPods 1.16.2 + homebrew Ruby 4.0.3 incompatibility.** `pod install` crashes with `Encoding::CompatibilityError: Unicode Normalization not appropriate for ASCII-8BIT` because Ruby 4.x's String API tightened around ASCII-8BIT vs UTF-8. Workaround: `LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8` before any CocoaPods invocation. Long-term fix: install Ruby 3.3 via rbenv and switch CocoaPods to use it.

- **`_layout.tsx` cold-launch import path is small.** Confirmed via grep: only `expo-router`, `expo-splash-screen`, `expo-font` (with 9 Google Fonts), `@react-native-async-storage/async-storage`, `firebase`, `@tanstack/react-query`, `react-native-gesture-handler`. Plus the auto-linked native modules from `package.json`. Bisecting which one triggers the crash is tractable if we can repro locally.

- **Backend reliability incident.** A story-gen request 80% complete (story `32d83efb-…`, had story text + 1 char ref + title page; was generating page 1) was orphaned when the Cloud Run instance died after a `TypeError: fetch failed sending request` blip to Gemini. New instance booted but didn't pick up the orphan. Mobile waited until 10-min timeout. Document `b1687687-…` succeeded on retry — backend itself is functional, just brittle to instance churn during 5-minute requests. Filed as FC-017.
